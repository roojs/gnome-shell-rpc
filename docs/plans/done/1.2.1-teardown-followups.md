**ℹ️** 2026-10-03 17:43–18:17, off code (gdb wrapper `/tmp/gsr-server-gdb-redraw.sh` + `/tmp/gsr-redraw.gdb`, stops on `SIGUSR2`; captures with `xwd` on `:3`):

## 5. Give-up dialog: "the shell has crashed", then log out

**ℹ️** User 2026-10-04: after give-up the user sees a black screen and their windows, with no explanation and no way to end the session. They need a message that the shell crashed and cannot recover, time to close their applications, then a way to log out.

**🚫** A dialog program (`zenity` etc.): no new dependency just for this (user 2026-10-04).

**🚫** "Not Yet" / re-show timers (user 2026-10-04).

**🚫** One strip with message + button, above the windows (user 2026-10-04: covers the user's windows; message and log out are two separate things).

**🚫** Message on the backdrop under the windows (user 2026-10-04: not helpful there; it must be on top of everything and cleared first).

**💩** `✔️` `Server.on_crash()` (called from the give-up branch, replaces the §3 inline backdrop) builds the whole screen with `Clutter` only:

1. §3 backdrop at the bottom of the stage.
2. The words "Log Out" at the top right, on the backdrop **under** the windows. Reactive; a click calls `on_crash_logout()`.
3. A full-screen notice **over** everything (90% black, reactive so it takes the clicks): "GNOME Shell has crashed and could not be restarted. Save your work and close your applications, then use Log Out at the top right of the screen." and an "OK" box under it. OK destroys the notice.

**💩** `⏳` "Log Out" ends the session:

- Real session: `org.gnome.SessionManager.Logout(1)` on the session bus (1 = no confirmation), async so the compositor does not block. That is the same call `gnome-session-quit --logout --no-prompt` makes; no new dependency.
- `Logout` fails (no bus, no session manager, call error): `GLib.error`. There is nothing left to recover to; aborting the compositor ends the session, which is what the user asked for. A warning would leave them stuck on the crash screen (user 2026-10-04).
- Nested test session: the session bus is the **host's**, so `Logout` would log out the real desktop. When the backend is `MetaBackendX11Nested` (mutter started with `--nested`, as `scripts/nested-weston-hold.sh` does), call `Meta.Context.terminate()` instead, so only the nested mutter exits.

#### Replace with — new method on `Server` (`src/server/rpc/Server.vala`, after `spawn_client`)

```vala
		/**
		 * "Log Out" on the give-up screen. Nested: only this mutter exits.
		 * Failure aborts: there is no shell left to recover to.
		 */
		private async void on_crash_logout()
		{
			var context = this.display.get_context();
			if (context.get_backend().get_type().name() == "MetaBackendX11Nested") {
				context.terminate();
				return;
			}
			try {
				var bus = yield GLib.Bus.get(GLib.BusType.SESSION);
				yield bus.call(
					"org.gnome.SessionManager", "/org/gnome/SessionManager",
					"org.gnome.SessionManager", "Logout",
					new GLib.Variant("(u)", 1), null,
					GLib.DBusCallFlags.NONE, -1, null);
			} catch (GLib.Error e) {
				GLib.error("log out: %s", e.message);
			}
		}
```

**ℹ️** `Clutter.Text`, `AlignConstraint`, `button_release_event` are all in the existing mutter 48 bindings. No St, no vapi change. Inline font and colour, because the shell's stylesheet goes with the shell.

**ℹ️** Input: with no shell, pointer events on stage actors still reach them (the shell's chrome was server-side actors on this stage the same way). Where a window covers "Log Out", the window gets the click.

**ℹ️** Prove with §4: `touch $XDG_RUNTIME_DIR/gsr-no-restart; pkill -u $(id -u) -x gsr-client`. Pass: message centred and "Log Out" top right on the backdrop, both under the terminal; terminal still usable; clicking "Log Out" in the nested session ends `gsr-server` cleanly (no crash in the log) and the host session is untouched.

**ℹ️** `✔️` 2026-10-04 nested run, notice + OK in `on_crash()`: give-up via §4 → notice over the terminal and the "Log Out" text; click OK → notice gone, terminal on top, "Log Out" top right, `gsr-server` alive.

**ℹ️** First version (message under the windows) implemented 2026-10-04, then replaced by the notice + OK above. Its "Log Out" click run: Nested run: give-up via §4; "Log Out" top right on the backdrop, terminal over the message; terminal closed → message centred; `xdotool` click on "Log Out" → `gsr-server` exits (`Meta.Context.terminate`), Weston auto-closes, no `log out:` error, no crash. ## 6. Crash screen at every client exit, with choices

**ℹ️** User 2026-10-04: show the §5 notice at **any** crash, not only at give-up, and let the user pick what happens. Replaces the automatic restart from 1.2.

**💩** `⏳` Every `gsr-client` exit (ready or not, including the 30 s not-ready kill) → teardown (as today) → `on_crash()`. No automatic `spawn_client()`. The notice says "GNOME Shell has crashed." and has four boxes in a row, same look as today's OK:

1. **Restart** — remove the crash screen, `spawn_client()`.
2. **Restart without extensions** — same, with extensions off for that client (see question 1).
3. **Emergency mode** — what OK does today: remove the notice only. The backdrop and "Log Out" at the top right stay. Window gather (unminimize, move to the active workspace) runs here, because no shell will restore them.

- The four boxes are the same actor with a different label and click: one `crash_choice(string label, owned GLib.SourceFunc pick)` builder instead of four copies of the OK block.

**💩** `⏳` §4 trigger file: no longer needed. `pkill -u $(id -u) -x gsr-client` reaches the crash screen on its own. Remove `gsr-no-restart`.
