## What we’re going to do

**🔷** Stop publishing Vala’s single `mutter-clutter-rpc-16.h` as `clutter/clutter.h`.

**🔷** Add a **header emitter** beside the Vala stub emitter. Both walk the same Clutter-16 typelib; headers are a **sibling** of `Generator`, not a subclass of the Vala class.

**🔷** Emit a **stock-shaped** include tree under something like `build/src/clutter-include/clutter/`:

```text
clutter/clutter.h                 ← umbrella
clutter/clutter-actor.h
clutter/clutter-enums.h
clutter/clutter-pango.h           ← umbrella over clutter/pango/…
…
```

St keeps `#include <clutter/clutter.h>` / `#include <clutter/clutter-pango.h>`; `.pc` `Cflags` point at that tree.

**🔷** Stage the work: **empty files first**, then fill types, then methods/vtables — so meson/St wiring can land before ABI is complete.

## Why not Vala headers / subclassing Generator

**ℹ️** Vala’s `.h` is one blob, pulls `ocrpc.h` / `gee.h`, and emits empty `ClutterActorClass { parent; }` — St writes `actor_class->allocate = …` and fails.

**ℹ️** Today’s `Generator` is a Vala emitter (`private emit_*`). A header writer does not need that. **Subclassing `Generator`** would inherit the wrong machine and still couldn’t call the private helpers.

**🔷** Extract shared walk/policy, then two siblings:

| Class | Role |
| --- | --- |
| `TypelibWalk` | require typelib, iterate infos, deny/overrides/type_policy, name helpers |
| `Generator` | Vala stubs (existing `emit`) — uses walk |
| `HeaderConfig` | `*.headers` layout (subdir, prefix, fixed, extra) — separate for now |
| `HeaderGenerator` | C headers (`emit-headers`) — uses walk + config |

CLI: `gi-stub-gen emit-headers NAMESPACE VERSION --outdir=… --headers-config=…` next to `emit`.

**⏳** **🔷** **Review (end of this plan):** if `HeaderGenerator` stays small, merge `HeaderConfig` into it. Keep them **separate while** Phase B–D grow the emitter.

## Phase A — Empty stock-shaped tree **🔷** **✔️**

**Goal:** Same *paths* St and stock use; files are valid C (include guards + optional umbrella `#include`s), **no** real type bodies yet.

### Steps

1. **✔️** **🔷** Extract `TypelibWalk` from `Generator` — deny/overrides/require/foreach info. Keep Vala `emit` working (Generator extends TypelibWalk).
2. **✔️** **🔷** Add `HeaderGenerator` + CLI `emit-headers NAMESPACE VERSION --outdir=DIR` + `--headers-config=FILE` (`Clutter.headers` for subdir/prefix/fixed/extra — not hardcoded in the walker).
3. **✔️** **🔷** From Clutter-16 typelib emit:
   - `clutter/clutter.h` — `__CLUTTER_H_INSIDE__` + `#include` list of sibling headers (empty stubs).
   - One empty `clutter/clutter-<kebab>.h` per object/struct/union/interface.
   - Fixed empties: `clutter-types`, `macros`, `main`, `enums`, `enum-types`, `clutter-pango.h`.
4. **✔️** **🔷** Meson: `custom_target` runs `emit-headers` into `clutter-include/`; stopped copying Vala `.h` → `clutter/clutter.h`.
5. **✔️** **🔷** `.pc` / `mutter_clutter_rpc_client_dep` `Cflags` → that outdir (`-I…/clutter-include`).
6. **Exit A ✔️:** `clutter.h` + `clutter-pango.h` present; one-liner `#include <clutter/clutter.h>` compiles.

## Phase B — Types in headers (structs / enums / object shells) **🔷** **✔️**

**Goal:** Headers declare the **shapes** St names — still may not subclass cleanly.

### Steps

1. **✔️** **🔷** **Enums / flags** → `clutter-enums.h` from GIR; values use `c:identifier` (`CLUTTER_ACTOR_ALIGN_CENTER`).
2. **✔️** **🔷** **Records** with GIR fields → e.g. `clutter-actor-box.h` (`x1`…`y2`); skip `*Private` / gtype structs as standalone files.
3. **✔️** **🔷** **Object / interface shells:** typedefs in `clutter-types.h`; per-type macros + `parent`/`priv` instance + parent-only class/iface structs; `GType …_get_type()`.
4. **✔️** **🔷** Opaque instance (no invented public fields); foreign field types use real ns (`CoglColor`) + includes.
5. **✔️** **🔷** Umbrella include order is parent-before-child; object headers `#include` same-ns parents.
6. **Exit B ✔️:** smoke `#include <clutter/clutter.h>` compiles with `ClutterActor`, `ClutterActorBox`, `CLUTTER_ACTOR_ALIGN_CENTER` (still no class vfuncs — Phase C).

## Phase C — Methods + class vfuncs St overrides **🔷** **✔️**

**Goal:** St `class_init` assignments compile; header ABI honest vs `.so`.

### Steps

1. **✔️** **🔷** Inventory St’s `actor_class->` / `content_iface->` / etc. writes (allocate, paint_node, child_added, …).
2. **✔️** **🔷** Emit those as **function pointers** on the generated class/iface structs (GIR virtual methods), in GIR `class_struct` order (prefer stock for reference — **🚫** copy stock trees).
3. **✔️** **🔷** Align stub `.so`: Vala `virtual` (`Namespace emit_class_slots=1` in `Clutter.overrides`) and/or C `G_DEFINE_TYPE` so slots exist at runtime — headers must not lie.
4. **✔️** **🔷** Instance method prototypes (`clutter_actor_*`) as declarations in the per-type headers; implementations stay in clutter-rpc `.so`.
5. **✔️** **🔷** **Header body overrides:** `{Type}.h` / `{Type}.methods.h` / fixed `clutter-*.h` under `header_override_dir` for surfaces GIR cannot express (Event, keysyms, macros, pango entry, varargs, array args, …).
6. **Exit C ✔️:** `ninja -C build gnome-shell/client-libs/libst-16.so` **compiles** against generated headers (link may already work from 0.7.2).

**ℹ️** Build split: Meta Vala keeps `-include mutter-clutter-rpc-16.h` + link-only Clutter dep; St uses `mutter_clutter_rpc_client_dep` → `clutter-include` only. `c-meta-shell-gaps.c` is a separate static lib with stock clutter `-I`.

### Generator backlog (later) **⏳** **🔷**

Hand overrides are fine for now. Later, prefer emit / **stock-fill** over growing curated files:

| Idea | Approach |
| --- | --- |
| **keysyms** | Grep `#define CLUTTER_KEY_*` from stock `clutter-keysyms.h` (or generate from same script mutter uses) — not hand lists |
| **macros / AUTOPTR / BOX_INIT** | Same: take stock `#define` / `G_DEFINE_AUTOPTR_*` lines we don’t already emit |
| **record methods** (`ActorBox`, `ActorIter`, …) | Emit GIR methods on structs (we already have symbols in `.so`) |
| **`const` / `GParamSpec` on protos** | Fix type/transfer mapping in `HeaderGenerator` |
| **stock-fill pattern** | Per stock file: symbols we already emit = known set; **anything remaining in that file** (macros, static inlines, extras) can be copied/adapted from stock into the generated header |

**ℹ️** Stock-fill is **not** vendoring whole mutter trees — only residual lines from the matching stock header after GIR emit. Overrides stay for true one-offs until each row above lands.
