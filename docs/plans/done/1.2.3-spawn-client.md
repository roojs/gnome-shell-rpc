# 1.2.3 — `SpawnClient` owns the shell client

**User goal:** `Server` stops owning client spawn. A new RPC class, `SpawnClient`, spawns `gsr-client`, watches it, draws the crash screen, and handles manual restart. `Meta.restart` and `Meta.is_restart` are intercepted in the client stub and sent to `Server-Rpc-SpawnClient`. `Server` does not register itself as `Meta`.

Alt+F2 `r` from [`1.2.2-x11-manual-restart.md`](1.2.2-x11-manual-restart.md) stays the same from the shell's point of view: the compositor stays up, that exit does not open the crash screen, and the new shell's `Meta.is_restart()` is true so layout skips the startup animation.

Checklist: `docs/guide-to-writing-plans.md`.

**Status:** **✅** user 2026-10-05. Archived.

Named for the coding-standards gate (do not add others):

- class `Gsr.Server.Rpc.SpawnClient`
- field on `Gsr.Server.Rpc.Server`: `spawn`
- fields on `SpawnClient`: `display`, `listen`, `rpc_socket_path`, `smoke_client`, `client_proc`, `manual_restart`, `client_is_restart`, `crash_actors`
- methods that move onto `SpawnClient` (same names): `spawn_client`, `restart`, `is_restart`, `on_crash`, `crash_choice`, `on_crash_logout`
- client methods in `Meta.override.vala`: `restart`, `is_restart` (stock names; bodies replace the generated GI calls)

## 1. What is wrong now

**ℹ️** [`1.2.2`](1.2.2-x11-manual-restart.md) §3 registers `Gsr.Server.Rpc.Server` as `Meta` for `restart` and `is_restart` only. FFI wins over `OLLMrpc.Gi.register("Meta")`, so those two wire methods never reach mutter, and every other `Meta.*` still does. That is already in `src/server/rpc/Server.vala`.

**ℹ️** The generated client already has `Meta.restart` and `Meta.is_restart`. They RPC to `Meta.restart` / `Meta.is_restart`. Stock JS (`layout.js` `_prepareStartupAnimation`, and `restart.js` after 1.2.2) calls those names. The intercept belongs next to `Meta.get_display`, which is a client override that calls `Server-Bootstrap.get_display` and never pretends the server object is `Meta`.

**ℹ️** Spawn is the rest of the overload. `Server` also owns `spawn_client`, the 30 s not-ready kill, `wait_async`, the two restart flags, and the crash screen (`on_crash`, `crash_choice`, `on_crash_logout`). Window tracking and the connection's actor teardown are separate and stay on `Server`.

**🚫** A separate OS process for spawn management. `SpawnClient` is a class in `Gsr.Server.Rpc`.

**🚫** Edits under `vendor/gnome-shell`. `restart.js` keeps calling `Meta.restart`. The stub is the intercept.

**🚫** `mutter-restart-helper`, and calling stock `meta_restart`. `SpawnClient.restart` does not emit `Meta.Display::restart`, so `main.js` does not call `reexec_self`. Same as 1.2.2.

**🚫** Moving window notification, `track_window`, or the `connection_ready` actor teardown (`stopping` / `stopped` in `Server.start`) onto `SpawnClient`.

## 2. `SpawnClient`

**🔷** `✔️` New `src/server/rpc/SpawnClient.vala`. It is the only type that spawns `gsr-client`. Wire name `Server-Rpc-SpawnClient`, the `Gsr.Server.Rpc.SpawnClient` path. `spawn_client` is public so `Server.start` can call it. The moved `??` expressions are ternaries.

`spawn_client`, the `wait_async` callback, `on_crash`, `crash_choice`, and `on_crash_logout` move unchanged from `Server`. `this` in those bodies is the `SpawnClient`. `restart` and `is_restart` move unchanged too: set `manual_restart`, reply, `force_exit` on idle; `is_restart` replies `client_is_restart`. A crash, the 30 s not-ready kill, and the crash screen's Restart still leave `client_is_restart` false.

#### Add — `src/server/rpc/SpawnClient.vala`

```vala
namespace Gsr.Server.Rpc
{
	/**
	 * {@code gsr-client} child: spawn, manual restart, crash screen.
	 *
	 * Client {@code Meta.restart} / {@code Meta.is_restart} call
	 * {@code Server-Rpc-SpawnClient}. This class does not register as {@code Meta}.
	 *
	 * == Example ==
	 *
	 * {{{
	 * Gsr.Server.Rpc.SpawnClient.rpc_register();
	 * var spawn = new Gsr.Server.Rpc.SpawnClient(display, listen, socket_path);
	 * OLLMrpc.Request.register("Server-Rpc-SpawnClient", spawn);
	 * spawn.spawn_client();
	 * }}}
	 */
	public class SpawnClient : GLib.Object
	{
		private global::Meta.Display display;
		private Listen listen;
		private string rpc_socket_path;
		private global::Meta.WaylandClient? smoke_client = null;
		private GLib.Subprocess? client_proc = null;
		private bool manual_restart = false;
		private bool client_is_restart = false;
		private Gee.ArrayList<global::Clutter.Actor> crash_actors {
			get; set; default = new Gee.ArrayList<global::Clutter.Actor>();
		}

		public static void rpc_register()
		{
			OLLMrpc.Request.add_class(
				"Server-Rpc-SpawnClient", typeof(SpawnClient),
				"restart", "so",
				"is_restart", "",
				null);
		}

		/**
		 * @param display compositor display used to spawn and to paint the crash screen
		 * @param listen RPC listener; readiness and teardown run on its connections
		 * @param rpc_socket_path value exported as {@code MUTTER_RPC_SOCKET}
		 */
		public SpawnClient(
			global::Meta.Display display,
			Listen listen,
			string rpc_socket_path)
		{
			this.display = display;
			this.listen = listen;
			this.rpc_socket_path = rpc_socket_path;
		}
	}
}
```

The six methods from `Server` are pasted into this class after the constructor. Their doc comments move with them.

#### Add — source list (`src/meson.build`, `compositor_sources`, after `server/rpc/Server.vala`)

```meson
  'server/rpc/SpawnClient.vala',
```

#### Add — boot (`src/server/rpc/Server.vala` `start`, with the other `rpc_register()` calls)

```vala

```

#### Add — instance (`Server.start`, after `this.listen = new Listen…`, before `listen.start()`)

```vala
			OLLMrpc.Request.register("Server-Rpc-SpawnClient", this.spawn);
```

```vala

```

## 3. Client intercept

**🔷** `✔️` Deny the generated GI bodies so they cannot RPC to mutter `meta_restart` / `meta_is_restart`. Hand methods in `Meta.override.vala` keep the stock names GJS already calls. Same pattern as `keybindings_set_custom_handler`: bare deny, body spliced into `namespace Meta`.

`restart.js` is unchanged. It still calls `Meta.restart(_('Restarting…'), global.context)`. `layout.js` still calls `Meta.is_restart()`.

#### Add — permanent deny (`src/client/libmutter-rpc-16/Meta.deny`, next to `keybindings_set_custom_handler`)

```
# Hand: Meta.override.vala → Server-Rpc-SpawnClient. Must not call mutter meta_restart.
restart
is_restart
```

#### Add — `src/client/libmutter-rpc-16/overrides/Meta.override.vala` (after `get_display`)

```vala
	/**
	 * Alt+F2 {@code r}. Compositor stays up; {@code Server-Rpc-SpawnClient} replaces
	 * {@code gsr-client}. Does not call stock {@code meta_restart}.
	 *
	 * @param message text stock mutter would show; ignored here
	 * @param context stock {@link Context}; ignored here
	 */
	public void restart(string? message, Context context)
	{
		Gsr.Client.Rpc.call_value(
			"Server-Rpc-SpawnClient.restart",
			null,
			OLLMrpc.args("so", message, context));
	}

	/**
	 * True when this client was spawned by a manual restart.
	 *
	 * @return {@code client_is_restart} on {@link Gsr.Server.Rpc.SpawnClient}
	 */
	public bool is_restart()
	{
		var response = Gsr.Client.Rpc.call_value("Server-Rpc-SpawnClient.is_restart");
		return response.retval.get_boolean();
	}
```

## 4. `Server` drops spawn

**🔷** `✔️` After §2, `Server` boots the socket, registers the other RPC classes, exports windows, and tears shell actors down when a connection stops. It holds `spawn` so the instance stays alive. It does not spawn, and it does not answer `Meta.*`. `spawn` is a private property set in `start()`, same as `listen`: a bare field would be unset after construction.

#### Remove — fields (`src/server/rpc/Server.vala`)

```vala
		private global::Meta.WaylandClient? smoke_client = null;
		private string rpc_socket_path = "";
		private GLib.Subprocess? client_proc = null;
		private bool manual_restart = false;
		private bool client_is_restart = false;
		private Gee.ArrayList<global::Clutter.Actor> crash_actors {
			get; set; default = new Gee.ArrayList<global::Clutter.Actor>();
		}
```

#### Add — property (after `ui_display`)

```vala
		private SpawnClient spawn { get; set; }
```

`start()` keeps a local `socket_path` and passes it into `SpawnClient`. It no longer stores `this.rpc_socket_path`.

#### Remove — `Meta` registration (`Server.start`)

```vala
			OLLMrpc.Request.add_class(
				"Meta", typeof(Gsr.Server.Rpc.Server),
				"restart", "so",
				"is_restart", "",
				null);
			OLLMrpc.Request.register("Meta", this);
```

#### Remove — from `Server`

`spawn_client`, `restart`, `is_restart`, `on_crash`, `crash_choice`, `on_crash_logout`. They live on `SpawnClient` only.

#### Replace with — class doc comment on `Server`

## 5. Prove scripts follow the wire name

**ℹ️** Nested prove treats `method=Meta.is_restart` in the client log as A4 (`layout.js` reached `_prepareStartupAnimation`). After §3 that call is logged as `method=Server-Rpc-SpawnClient.is_restart`.

**🔷** `✔️` Point the A4 pattern at the new method.

#### Replace with — `scripts/nested-weston-prove.sh`

```bash
# Stock path: Server-Rpc-SpawnClient.is_restart means _prepareStartupAnimation ran (A4 proxy until
# a non-override startup-complete marker exists).
# GSR_NESTED_NO_A4=1 — keep running after A4 (stay-up / post-READY extension spawn).
A4_PAT='method=Server-Rpc-SpawnClient\.is_restart'
```

#### Replace with — `scripts/nested-init-prove.sh`

```bash
A4_PAT='method=Server-Rpc-SpawnClient\.is_restart'
```

#### Replace with — the A4 sentence in `docs/nested-debug.md`

`READY=1` + `method=Server-Rpc-SpawnClient.is_restart` on a **default prove** usually means A4 succeeded and the script killed the nest ~0.3s later. That is progress, not a SEGV.
