# 0.8.3 — Harden `rpc_lid` from GJS

**Status:** **✔️** 2026-10-05. User chose **H1** only, then archive. H2–H4 not done.

**User goal:** keep wire lease handles as RPC plumbing, not something GJS
(or extensions) can casually read or reassign.

**Landed:** `[CCode (gir = false)]` on `rpc_lid` in the generator and on the
hand stubs that declare it (`Shell.GLSLEffect`, `Shell.BlurEffect`,
`Shell.InvertLightnessEffect`, `Meta.RpcSubprocess`). The matching
`rpc-lid` property is removed from `Gsr-1.0.gir` (that file is hand-written;
valac does not emit it). The GObject property stays, so Bin
`Object.new(…, "rpc-lid", handle)` still injects the lease.

**Context:** `OLLMrpc.Live.Handle.rpc_lid` (GObject name `rpc-lid`) is a
construct property on every leased stub so Bin live-decode can
`Object.new(…, "rpc-lid", handle)` and stub construct can skip remint.
Discussed 2026-09-14 in-session — stock shell JS does not name it; typelib
often omits it; the GType still installs it **readable + writable**.

---

## Why

| Fact | Risk |
| ---- | ---- |
| `g_param_spec_uint64 ("rpc-lid", … READABLE \| WRITABLE \| CONSTRUCT)` on Handle implementors | Anything that sets GObject props by name can retarget a proxy to another lease |
| Not a stock Meta/Clutter/St symbol | Normal chrome will not use it; not “API pollution” for layout.js |
| `[CCode (gir = false)]` | Hidden from GIR/typelib. GObject prop remains |

**Closed on:** GJS property APIs that follow the typelib do not see
`rpc-lid`. Lease inject for Bin/overrides is unchanged.
