## Phase 1 — Drop dead client handling

No new methods. No `throws` added on `Runtime.call_values`.

### 1. `src/gi-stub/Runtime.vala` — `do_call`

**Why:** `call.end` already throws. The `response.error` check is dead. Keep aborting the GI client process on failure (existing policy).

**Where:** after the `call_loop.run()` block.

#### Remove

```vala
			if (call_error != null) {
				GLib.error("%s", call_error.message);
			}
			if (response.error != null) {
				GLib.error("%s", response.error.message);
			}
			for (var i = 0; i < response.result.size; i++) {
```

#### Replace with

```vala
			if (call_error != null) {
				GLib.error("%s", call_error.message);
			}
			for (var i = 0; i < response.result.size; i++) {
```

### 2. `src/fake-shell/Session.vala` — `call`

**Why:** 8.4.4 named this wrap. `Session.call` already `throws GLib.Error`.

**Where:** `FakeShell.Session.call`.

#### Remove

```vala
		public async OLLMrpc.Response call(OLLMrpc.Request request) throws GLib.Error
		{
			var response = yield this.client.call(request);
			if (response.error != null) {
				throw new GLib.IOError.FAILED(response.error.message);
			}
			return response;
		}
```

#### Replace with

```vala
		public async OLLMrpc.Response call(OLLMrpc.Request request) throws GLib.Error
		{
			return yield this.client.call(request);
		}
```

### 3. `src/rpc-client/Application.vala` — `run_client`

**Why:** same dead wrap. Method already `throws`.

**Where:** after `list_windows` `call`.

#### Remove

					method = "Meta-Display.list_windows",
				}

## Phase 2 — Generator emits `throws` (GIR `THROWS` only)

The generator never looks at `GI.FunctionInfoFlags.THROWS`. Wired methods are always `public $(ret) $(name)($(arglist))` with no `throws`. GJS therefore cannot see a GError as a JS exception — and today `Runtime.do_call` still `GLib.error`-aborts before anything could throw out.

- **🔷** `✔️` Generator: when `(flags & GI.FunctionInfoFlags.THROWS) != 0`, emit `throws GLib.Error` on the stub signature (wired, noop, not_wired, iface). Constructors too if they throw.
- **🔷** `✔️` Methods that do **not** throw keep today’s signature and call `call_values` as today. **No** `try` / `catch`. Vala unhandled-error warnings are expected — those GIR methods do not throw.
- **🔷** `✔️` `Runtime.call_values` / `call_object` / `call_list` / `do_call`: `throws GLib.Error`; rethrow `call_error` instead of `GLib.error`. Without this, generated `throws` never runs.

Hand `call_values` sites (overrides, `meta-mini`, `callback_bind`) stay as they are. Same unhandled-error warnings.

**🚫** Do not wrap generated `call_values` in `try` / `catch`. **🚫** Do not add `throws` to every generated Meta method. **🚫** Do not add a second Runtime helper (`call_values_throws`).
