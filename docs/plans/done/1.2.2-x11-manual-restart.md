# 1.2.2 — X11 manual restart (`r`)

**User goal:** Alt+F2, `r` restarts the shell. The shell's "Restart is not available on Wayland" check is patched out, because the compositor stays up. That exit is a manual restart, so the crash screen stays out of it. The new shell sees `Meta.is_restart()`, and skips the startup animation.

Checklist: `docs/guide-to-writing-plans.md`.

**Status:** **✅** user 2026-10-05. Archived. Alt+F2 `r` is in the tree. The `Meta` intercept lives on `SpawnClient` ([`1.2.3-spawn-client.md`](1.2.3-spawn-client.md)).

**ℹ️** §3 registers `Server` as `Meta` for `restart` and `is_restart`. That intercept is the wrong home. [`1.2.3-spawn-client.md`](1.2.3-spawn-client.md) moves spawn, the crash screen, and those two calls onto `SpawnClient`, and intercepts `Meta.restart` / `Meta.is_restart` in the client stub. The `r` behaviour in this plan stays.

Named for the coding-standards gate (do not add others):

- fields on `Gsr.Server.Rpc.Server`: `manual_restart`, `client_is_restart`

## 1. What `r` does

**ℹ️** Stock shell, `vendor/gnome-shell/js/ui/runDialog.js`. Alt+F2 accepts `r` and `restart`. `_restart()` calls `Meta.is_wayland_compositor()`. On Wayland it shows "Restart is not available on Wayland" and returns. On X11 it closes the dialog and calls `Meta.restart(_("Restarting…"), global.context)`.

**ℹ️** `vendor/gnome-shell/js/ui/main.js` connects `global.display` `restart` to `global.reexec_self()`. `js/ui/layout.js` skips the startup animation when `Meta.is_restart()` is true (`_prepareStartupAnimation`, `_startupAnimation`).

**ℹ️** Stock `meta_restart` runs in the compositor process. It emits `show-restart-message`, sets a process-global restart flag, emits `restart`, and spawns `/usr/libexec/mutter-restart-helper` to hold the X composite overlay while that process is replaced.

**ℹ️** Here the compositor is `gsr-server` and the shell is `gsr-client`. `OLLMrpc.Gi.register("Meta")` sends `Meta.restart` and `Meta.is_restart` to those mutter functions inside `gsr-server`. `Shell.Global` has no `reexec_self`. On X11, `r` hits `meta_restart` in the compositor, then `global.reexec_self()` throws, and the client stays up.

**ℹ️** `wait_async` in `src/server/rpc/Server.vala` calls `on_crash()` on every client exit. Once `r` does replace the client, that exit opens the crash screen.

**🚫** Edits under `vendor/gnome-shell`. The run dialog and `main.js` stay as they are.

**🚫** `mutter-restart-helper`, and calling stock `meta_restart` from `gsr-server`. The compositor stays up. Only the shell client is replaced.

## 2. Patch out the Wayland refusal

**🔷** `✔️` `RunDialog._restart` returns immediately when `Meta.is_wayland_compositor()` is true, and shows "Restart is not available on Wayland". Our compositor stays up, so that check does not apply. After `init.js` has loaded, assign `_restart` on that class. `vendor/gnome-shell` stays untouched.

`main.js` imports `ui/runDialog.js` while `init.js` loads. The dialog object is created on the first Alt+F2, and `_init` binds `this._restart` then. Assigning the prototype after `init.js` and before that first open is the overwrite.

#### Add — `src/client/gresource/restart.js`

```javascript
import Meta from 'gi://Meta';
import {RunDialog} from 'resource:///org/gnome/shell/ui/runDialog.js';

RunDialog.prototype._restart = function () {
    this._shouldFadeOut = false;
    this.close();
    Meta.restart(_('Restarting…'), global.context);
};
```

#### Add — resource entry (`src/client/gresource/gsr-js-resources.gresource.xml`)

```xml
    <file>restart.js</file>
```

#### Add — eval after `init.js` (`src/client/ShellApplication.vala`)

When the script just eval'd is `init.js`, `ctx.eval_module_file` on `resource:///org/gnome/shell-rpc/restart.js`. Smokes do not load it.

## 3. Flag the exit, then spawn

**🔷** `✔️` `Meta.restart` sets `manual_restart` and ends the client. The wait callback sees that, tears down, spawns the next client, and does not call `on_crash()`. It then clears `manual_restart` and sets `client_is_restart`, which is what `Meta.is_restart` returns for that client. A crash, the 30 s not-ready kill, and the crash screen's Restart leave `client_is_restart` false. Two flags, because the exit flag has to be consumed before the next exit, and the new shell still has to be told it is a restart.

#### Add — fields on `Server` (`src/server/rpc/Server.vala`, after `client_proc`)

```vala
		private bool manual_restart = false;
		private bool client_is_restart = false;
```

#### Add — handlers on `Server`, registered from `start()`

The generated client already calls `Meta.restart` and `Meta.is_restart`. FFI runs before GI, and only the methods listed here, so the rest of `Meta.*` still goes to mutter. `restart` sets the flag and ends the client. It does not call stock `meta_restart`, and it does not emit `restart`, so `main.js` does not call `reexec_self`. `is_restart` replies `client_is_restart`.

```vala
		public void restart(OLLMrpc.Request request, string? message, global::Meta.Context context)
		{
			this.manual_restart = true;
			request.reply(new OLLMrpc.Response() {
				id = request.id,
			});
			var proc = this.client_proc;
			GLib.Idle.add(() => {
				if (proc != null && this.client_proc == proc) {
					proc.force_exit();
				}
				return GLib.Source.REMOVE;
			});
		}

		public void is_restart(OLLMrpc.Request request)
		{
			request.reply(new OLLMrpc.Response() {
				id = request.id,
				retval = OLLMrpc.val("b", this.client_is_restart),
			});
		}
```

```vala
			OLLMrpc.Request.add_class(
				"Meta", typeof(Gsr.Server.Rpc.Server),
				"restart", "so",
				"is_restart", "",
				null);
			OLLMrpc.Request.register("Meta", this);
```

#### Remove — exit path in the `wait_async` callback (`src/server/rpc/Server.vala`)

```vala
					var was_ready = false;
					foreach (var connection in this.listen.connections.to_array()) {
						was_ready |= ((Gsr.Server.Rpc.Connection) connection).ready;
						connection.stop();
					}
					this.listen.connections.clear();
					GLib.debug("client exited ready=%s", was_ready.to_string());
					this.on_crash();
```

#### Replace with — exit path

```vala
					foreach (var connection in this.listen.connections.to_array()) {
						connection.stop();
					}
					this.listen.connections.clear();
					var manual_restart = this.manual_restart;
					this.manual_restart = false;
					GLib.debug("client exited manual-restart=%s", manual_restart.to_string());
					if (manual_restart) {
						this.client_is_restart = true;
						this.spawn_client();
						return;
					}
					this.client_is_restart = false;
					this.on_crash();
```

**ℹ️** Prove, nested session: Alt+F2, `r`, Enter. Pass: log shows `client exited manual-restart=true`, then `spawned`, and no crash notice. The new client's `Meta.is_restart` is true. A later `pkill -u $(id -u) -x gsr-client` shows the crash screen.
