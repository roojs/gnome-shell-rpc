## Purpose

- **🔷** Compositor plugin (RPC **server**) starts the shell client after the socket is listening.
- **🔷** Monitor that child; respawn on exit (with backoff).
- **🔷** Opposite polarity from ollmfilesd / `OLLMrpc.ClientBoot` (there the **client** starts the **daemon**).

---

## Polarity vs files daemon

| | Files daemon | gnome-shell-rpc |
|---|---|---|
| Who listens | `ollmfilesd` | mutter plugin (`SocketListen`) |
| Who connects | CLI / app | fake shell / real shell |
| Who spawns whom | client spawns server | **server spawns client** |
| Ready probe | “can I connect to the socket?” | “has the child connected / said hello?” |
| Env on spawn | `--data-dir`, socket under data dir | `MUTTER_RPC_SOCKET`, `WAYLAND_DISPLAY`, nested session vars |

**Reusable from `ClientBoot` (pattern, not class):** `spawn_async`, pid file, startup poll, SIGTERM + grace + respawn, “already running?” check.

**🚫** Do not point `ClientBoot` at `mutter-rpc.sock` — it may unlink the socket and spawn `ollmfilesd`.
