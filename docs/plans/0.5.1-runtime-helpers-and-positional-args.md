## Purpose

Two related problems after the Meta mini smoke:

1. **🔷** `✔️` **`GiStub.Runtime` helpers** — stubs no longer hand-parse `OLLMrpc.Response` in every method.
2. **🔷** `⏳` **Params at Meta scale** — drop per-method `*Params` where the typelib FFI path applies. Args are **positional** `GLib.Value`s in GIR order — **no direction on the wire** (libocrpc 8.4.1).

**🚫** Do not invent Meta methods. Helpers live on **`GnomeShellRpc.GiStub.Runtime`** (ours).

## libocrpc wire shape (fact — 8.4)

| Piece | Role |
|-------|------|
| `Request.param` | Legacy `CallParam` bag — still valid; empty `values` omitted |
| `Request.values` | Positional `GLib.Value?` list, GIR / C order |
| `Request.lease_id` | Leased instance for typelib **methods** (not in `values`) |
| `Response.result` | Returned / exported `GObject`s |
| `Response.values` | Scalar returns and OUT args (int, string, bool, …) |
| `Gi.register(ns, ver)` | Server: wire aliases `Meta-Window`, … → stock typelib |
| `Gi.dispatch()` | After hand `Request.register` handlers; FFI invoke on lease |

**ℹ️** Direction (IN / OUT / INOUT) comes from the typelib at invoke time — **not** sent as `(dir, value)` pairs. The old 0.5.1 sketch with `Arg.IN = 1` on the wire is **withdrawn**.

**ℹ️** Hand `Meta-Display.*` handlers still win over `Gi` for the same wire prefix (`Request.dispatch` order).

## B — Positional args (replace `*Params` where FFI applies)

**🔷** `⏳` Client stub: build `Request.values` in GIR order; set `lease_id` for instance methods.

```vala
Runtime.call_values("Meta-Window.minimize", win);
var t = GLib.Value(typeof(uint32));
t.set_uint(42);
Runtime.call_values("Meta-Some.method", win, { t });
var n = Runtime.call_values("Meta-Some.query", win).values.get(0).get_int();
```

**🚫** No per-method `*Params` for GenClient-scale emit (keep `DisplayParams` only while hand `Meta-Display` handlers exist).

**ℹ️** GObject args in `values` when libocrpc `Gi.convert` grows OBJECT support (8.4.5 leftovers). Until then, instance = `lease_id`; extra GObject args may still need hand handlers or snapshots.
