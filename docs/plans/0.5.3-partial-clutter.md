## Problem

Out-of-process client loads **real libclutter** and our **Meta stub `.so`**. Generated types such as `Meta.WindowActor` subclass `Clutter.Actor`.

GObject dispatch:

| Call | Lands in |
|------|----------|
| `windowActor.freeze()` | Meta stub → RPC ✔️ |
| `windowActor.show()` | **libclutter** on a hollow client actor ✘ |

Extension authors cannot be told to avoid Clutter. **Compositor-backed** actors need a **lease proxy** that forwards selected Clutter APIs to the server. **Local `St` chrome** still uses real libclutter on a client stage (later).

**ℹ️** GIR often types list returns as `Clutter.Actor` when elements are really `Meta.WindowActor` (`Compositor.get_window_actors`). Vala metadata already fixes this; our generator needs an **override** file (same idea as `Meta-16.metadata`).

---

## Goal

**🔷** **Partial Clutter** — not shadowing all of `Clutter-16`. Only forward Clutter methods on **leased** instances of types Meta exposes (`WindowActor`, returned `Clutter.Actor` leases, …).

**🔷** **POC:** one round-trip — `compositor.get_window_actors()[0].show()` hits server `Clutter.Actor.show` on the real `MetaWindowActor`.

**🚫** Full paint pipeline, stage hosting, `St` on client — see approach B in 0.5 (remote stage). This plan is **lease forwarding**, not renderer relay.

---

## Architecture

```text
GJS  →  Meta.WindowActor.show()
         └─ override in stub .so (leased?)
              ├─ yes → Runtime.call_values("Clutter-Actor.show", this)
              └─ no  → base Clutter.Actor.show()  (local St widgets)
Server Gi.dispatch → real MetaWindowActor (is Clutter.Actor)
```

**Wire names:** use stock GI aliases — `Clutter-Actor.show`, not invented Meta symbols.

**Lease id:** client stub carries `gsr-lease-id` (or synced from `Client.proxies` after decode). Server resolves `Request.lease_id` → live pointer.

## POC scope (this repo)

### Server

**Add:**

- `Gi.register("Clutter", "16")` beside Meta (mutter typelib dir has `Clutter-16.typelib`).
- `RPC-Bootstrap.get_display` — export real `Meta.Display`, return lease id in `Response.values` (bootstrap gap until `Meta.get_display()` is a real constructor RPC).

### Generator

**Add:**

- `src/gi-stub-gen/Meta.overrides` — `Type.method list_elem=WindowActor` (and similar).
- Wire `Compositor.get_window_actors` as `GLib.List<WindowActor>` despite GIR `Clutter.Actor`.

**Remove:**

- `unmapped_return` gap for `Meta-Compositor.get_window_actors` (moves to wired or deny list).

### Client (`meta-mini` spike)

**Add:**

- `GnomeShellRpc.GiStub.ClutterLease` — forward leased `Clutter.Actor` methods via `call_values`.
- `Meta.WindowActor` — `show` / `hide` / `get_visible` overrides (POC trio).
- `Meta.Compositor.get_window_actors()` — `call_values` + list unpack.
- `Meta.Display.get_compositor()` — needs display lease from bootstrap.
- `Runtime.attach_lease()` — copy `Client.proxies` handle → `gsr-lease-id` on decoded GObjects.

### Smoke

**Add:**

- `src/gjs-embed/clutter-smoke.js` — launch app, `get_compositor().get_window_actors()`, `actor.show()` (requires typelib with POC stubs).

**Run (nested only):**

```bash
# compositor already running gnome-shell-rpc with socket
GI_META_SMOKE_CLUTTER=1 ./build/src/gjs-embed --debug src/gjs-embed/clutter-smoke.js
```
