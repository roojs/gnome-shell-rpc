# 1.2.5 — Server start and exit in the journal

**User goal:** An alan2 greeter login shows, in the journal, whether `gsr-server` started and why it exited. No `--debug`. The shell client is not part of this.

Checklist: `docs/guide-to-writing-plans.md`.

**Status:** **✔️** implemented 2026-10-04. Not user-approved yet.

**ℹ️** 2026-10-04 12:02. Two alan2 logins opened and closed in the same second. GDM: `Session never registered, failing`. No `gsr-client`, and no `gsr-server` line. The previous session was still stopping (`TransactionIsDestructive`).

Named for the coding-standards gate (do not add others):

- none

---

## 1. What is wrong now

**ℹ️** `Gsr.Server.CompositorApp.run` (`src/server/Main.vala`) prints `error:`, `Error initializing:`, `Failed to setup:`, and `Failed to start:` on stderr, then returns. A normal end of `run_main_loop` prints nothing. Nothing prints on entry.

**ℹ️** `GLib.Log.set_default_handler` is installed before option parsing. After that, `ApplicationInterface.debug_log` is the stderr path. It prints when `--debug` is on, and it prints `LEVEL_CRITICAL` always. `GLib.debug` is the call. A direct stderr write after the handler skips that.

**🚫** A start or exit line on `gsr-client`.

**🚫** Registering the session with GDM. That is a later step, after a login shows whether the server ran.

**🚫** `--debug` on the greeter server.

---

## 2. One stderr line, then the handler

**🔷** `✔️` First line of `run`, before `set_default_handler`: `started`, then flush. The handler does not exist yet. After it does, the error returns and the end of `run_main_loop` are `GLib.debug`. No further stderr.

#### Add — entry (`src/server/Main.vala`, start of `run`)

```vala
			GLib.stderr.printf("started\n");
			GLib.stderr.flush();
```

#### Replace — error returns (same file)

```vala
				GLib.debug("Failed to setup: %s", e.message);
```

Same call for `error:`, `Error initializing:`, and `Failed to start:`.

#### Add — after `run_main_loop` returns

```vala
			GLib.debug("exit 0");
```

**ℹ️** Prove, after install, once alan2 is fully logged out: log in as alan2 once. `journalctl -b -o short-iso` for that minute. `started` means this process ran. No `started` means it never ran. The `GLib.debug` lines are in that journal when the server was started with `--debug`.
