# 0.9 — Multi shell series (one package per Ubuntu release)

**User goal:** Keep one git tree. Ship a separate package for each Ubuntu release we support, built on GitHub, and test each package on a virtual machine for that release. Each package is the RPC stack for that release’s GNOME Shell (`libmutter-rpc-16` on 25.04, `libmutter-rpc-18` on 26.04, and so on).

**Status:** **proposed** (user 2026-10-29). Not started.

Checklist: [`docs/guide-to-writing-plans.md`](../guide-to-writing-plans.md).

**ℹ️** Packaging shape is already decided in [`done/1.1-installable-bootable-session.md`](done/1.1-installable-bootable-session.md): one package name, `gnome-shell-rpc`, per distro release. Two generations are not installed side by side. `/usr/bin/gsr-server` stays one path.

## Purpose

- 🔷 Each phase is one Ubuntu release. GitHub Release builds that release’s package and publishes it on `v*-packages`. Proof is installing it on a virtual machine of that release and logging into the session.
- 🔷 Ubuntu 25.10 is skipped. The upgrade from 25.04 offers 26.04 LTS directly.
- ⏳ Phase 1 is Ubuntu 26.04. Phase 2 is Ubuntu 26.10, after the 26.04 package has been logged into.
- ℹ️ The Release job today is [`.github/workflows/x-debian.yml`](../../.github/workflows/x-debian.yml) (`ubuntu:25.04`, `ROOJS_APT_SUITE=plucky`). Publish is [`.github/workflows/release.yml`](../../.github/workflows/release.yml).

## Source layout

The new soname is **18**. `libmutter-17` is the skipped 25.10 release.

- 🔷 Leave a file in the old directory when that build still compiles it.
- 🔷 Move a file into the newest directory when its API did not change. The old build compiles that path.
- 🔷 Replace or add in the newest directory when that build does not use the old file. Replace is a new version of a file the old directory has. Add is a file the old directory does not have.

## LLM notes

- Do not create a numberless `libmutter-clutter` directory for shared code. The shared copy is the newest numbered directory.
- Do not add an Ubuntu 25.10 job, a `libmutter-17` package, or a questing control rewrite.
- Do not upgrade `/var/lib/libvirt/images/ubuntu 25.04_1.qcow`. It is the working 25.04 test machine.
- Do not build two Ubuntu releases in one container. One job, one mutter.
- Do not ship one `libmutter-rpc-*.so` that loads on the wrong shell.
- Do not start Phase 2 while doing Phase 1.
- Do not start the 26.04 package build while 0.9.1 is still open.
- Do not `meson install` onto the live host session.
- Fedora stays the existing `fedora:42` job. These phases do not add RPM images.
- A rolling `main` vendor build is not part of this plan.
