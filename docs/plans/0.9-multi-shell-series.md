# 0.9 — Multi shell series (separate RPC per release)

**User goal:** Bump the desktop by shipping **a different named RPC stack for each GNOME Shell generation** (`libmutter-rpc-16`, `libmutter-rpc-NN`, …) — **not** one binary/typelib that runs on every shell. **One git tree**, shared Vala/generator code; **each upstream shell release** (48, 50, …) gets its own built + installed artifacts. **Head** (`vendor` = `main`) is the rolling dev line on whatever mutter API head uses today.

Checklist: `docs/guide-to-writing-plans.md`.

**Status:** **BACKLOG** — start after **0.8** minimal bar is **✅** on **48**; first new target **50** (e.g. Ubuntu 26.04) is a **packaging coincidence**, not the axis of the design.

**Context:** [`README.md`](README.md) · vendor policy [`done/0.7-gnome-shell-rpc-client.md`](done/0.7-gnome-shell-rpc-client.md) · active [`0.8-init-complete-and-interaction.md`](0.8-init-complete-and-interaction.md).

**🚫** One `libmutter-rpc-*.so` that loads on the wrong shell · mixing typelibs from two generations in one `GI_TYPELIB_PATH` · starting 0.9 while 0.8 is open unless user parallel-tracks.

---

## ℹ️ Model (read this first)

| Track | What you build | What you run against |
| ----- | -------------- | -------------------- |
| **Pinned release** (48, 50, …) | `libmutter-rpc-NN`, `Meta-NN.typelib`, `St-NN` client typelib, plugin for that mutter | Distro **that** `gnome-shell` + **that** `libst-NN.so` + **that** JS tree |
| **Head** | Same naming rule: **NN = mutter API on `main`**, vendor at `main` + refresh | Dev/CI nested against head JS/GIR when proving |

**ℹ️** Ubuntu 25.04 vs 26.04 only matters because each ships a different **shell** version — we align **build target to shell/mutter API**, not to “Ubuntu series” as a first-class knob.

**ℹ️** Meson still does **one target per build directory** (today): `meson setup build-48 …` → install `*-16`; `build-50` → install `*-NN`. Optional later: one top-level meson that builds multiple subdirs — **still separate `.so` names**, not one merged library.

**ℹ️** Overrides / generator: **mostly shared source**; only fork files when a release’s GIR or C ABI differs (`header-overrides/NN/`, etc.).

---

## How we prove (every change)

1. **48:** `./scripts/nested-init-prove.sh` with **only** `libmutter-rpc-16` on `GI_TYPELIB_PATH`.
2. **50 (or next pin):** same script with **that** generation’s typelibs.
3. **Head:** prove job on CI with vendor refresh + mutter API read from `main`.
4. Configure prints **shell generation + mutter API `NN` + vendor SHA** — wrong distro packages = **configure error**.

## Done when

- **✅** Two **distinct named** RPC installs from one tree (e.g. `libmutter-rpc-16` and `libmutter-rpc-NN` for 50) — never interchangeable.
- **✅** **Head** CI builds the rolling `NN` from `main`.
- **✅** **0.8** prove passes on **48** and on the first newer pin (**50**).
