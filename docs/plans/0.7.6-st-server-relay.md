## Purpose

Stop trying to run **real `libst` C** in **`gnome-shell-rpc`** against **RPC Clutter stubs**. That dual stack cannot work: GJS creates `St.Widget` / `UiActor` locally, libst expects in-process Clutter actors, and every boot “fix” (`call_local`, no-op `add_child`, skip `BindConstraint` lease, …) hides the mismatch without reaching chrome.

**🔷** **St lives on `mutter-rpc` (server).** Client **`St-16.typelib`** is an **RPC relay** — same model as Meta and Clutter today.

**🔷** **`gnome-shell-rpc`** keeps GJS + distro JS only; it does **not** link **`libst-16.so`**.

---

## Architecture (target)

```
mutter-rpc (server)                         gnome-shell-rpc (client)
─────────────────────                       ──────────────────────────
real libmutter / libclutter                 libmutter-rpc-16 (Meta stub)
real libst / libshell (vendor)              libmutter-clutter-rpc-16 (Clutter stub)
  └─ stage, window_group, St.Widget…          └─ leased Meta/Clutter proxies
Rpc.Server + Gi.register("St","16")         libst-rpc-16 (NEW — generated relay)
  └─ St-* methods → real St C objects         └─ St-* → Runtime.call_values
GJS never runs here                           GJS: import St; new St.Widget(…)
                                              → server creates widget, returns stub + rpc_lid
```

**ℹ️** Clutter **stage / compositor actors** stay server-side (already leased to client). **St chrome** (`St.Widget`, `St.BoxLayout`, theme nodes, …) is also server-side; client holds **handles** only.

**ℹ️** GJS **subclasses** (`UiActor extends St.Widget`) still exist on the client as **JS types**, but their **C instance** must be a **leased server actor** (or a documented bootstrap exception), not a local-only stub actor.

**🚫** Do not invent St APIs not in real `St-16.gir` / typelib.

## What we learned (why boot probes are out)

| Boot probe | Problem |
| --- | --- |
| `Runtime.call_local` | Shadow props on unleased actors; wrong types; masks missing lease |
| No-op `add_child` / `add_constraint` when `rpc_lid==0` | Client tree diverges from server stage |
| Skip `BindConstraint.new` when source unleased | Constraints never exist on server |
| Client `libst` + stub Clutter ABI / header sizing (0.7.5) | Chasing layout of a stack we are abandoning on the client |

**✔️** Phase A below **reverts** these probes. Failures should again surface as **`no rpc_lid`** / RPC errors until relay + lease policy is in place.

## Phase A — Revert boot probes **🔷** **✔️**

**Remove:**

- `Runtime.call_local`, `local_props`, `wire_retval`, unleased-arg wire-as-`0`
- `Actor.override` no-ops (`add_child`, `remove_child`, `add_constraint`, local `get_accessible`)
- `BindConstraint.override` (constructed lease skip)
- Related `Clutter.deny` rows that only existed for those overrides

**Keep:**

- `OLLMrpc.Live.Handle` / `rpc_lid` on stubs (not `get_data("rpc-lid")`)
- `ActorIter.override` (RPC child walk — valid for leased tree)
- `Actor.override` `destroy_rpc` only (signal name clash)
- Generator / Meta–Clutter work unrelated to local St

**Exit:** nested boot fails at **explicit lease/RPC** boundaries again (e.g. `Gjs_ui_layout_UiActor` without `rpc_lid`), not random `g_type_interface_peek` from client libst.

## Phase B — Stock St on the server **🔷** **✔️**

**Compositor (`mutter-rpc`):**

- Use **distro** `libst-16.so` + `St-16.typelib` from `GNOME_SHELL_PKGLIBDIR` (same as Gvc) — **not** a vendored rebuild
- **`Rpc.Server`**: prepend pkglibdir, `Gi.register("St", "16")` (always, with Meta/Clutter)

**🚫** No `gnome-shell/server-libs/` — server uses stock GI like Meta/Clutter.

**Legacy (disabled by default):** `-Dgnome_shell_client_libs=enabled` + vendor checkout built vendored client `libst`/`libshell` against RPC stubs; superseded by Phase C St RPC stubs.

## Phase C — Client `St` RPC stubs **🔷** **✔️**

Mirror Meta/Clutter client stub pipeline:

- `gi-stub-gen` (or sibling) pass for **`St-16.gir`** → `St_generated.vala` + `libst-rpc-16.so` + `St-16.typelib`
- `Runtime.register()` loads `St.register()` + bins
- Methods/properties → `Runtime.call_values("St-Widget.…")` with `rpc_lid` lease
- Deny + overrides only for real ABI/signal clashes (same discipline as Clutter.deny)

**🚫** No client C `libst` sources compiled into `gnome-shell-rpc`.

**Exit:** `gjs -c 'imports gi; Gi.require("St","16");'` using **build** typelib talks to running `mutter-rpc` (smoke).

**✔️** Landed: `St.deny` / `St.overrides`, `libst-rpc-16.so`, build-tree `St-16.typelib`, `st_register()` in `Runtime.register()`, `st-rpc-load.js` nested smoke (`GI_META_SMOKE=st-rpc-load.js`). Generator: foreign GObject IN args + `GdkPixbuf` → `Gdk` Vala mapping. Server: `mutter-rpc` links stock `libst-16.so` by absolute path (`--no-as-needed`) — same model as Meta via `libmutter-16`, not runtime `Module.open`.

## Phase D — Lease policy for GJS-created actors **🔷** **✔️**

When GJS runs `new St.Widget({…})` or registers `UiActor extends St.Widget`:

1. Client stub **`constructed`** (or GJS hook) sends **`St-Widget.new`** (or documented factory) to server with construct properties.
2. Server creates real `StWidget`, adds to correct parent when wire says so, returns lease.
3. Client stub stores **`rpc_lid`**; all further St/Clutter calls RPC.

**Subclasses:** GJS vfuncs run on client; default C vfuncs that touch Clutter state must RPC or be overridden in JS to call server.

**Clutter children from layout.js:** `global.stage.add_child(uiGroup)` must RPC **both** sides with valid leases — no client-only no-ops.

**Exit:** nested gets past `layout.js` `UiActor` / `overviewGroup` without `call_local` or no-op tree hacks.

**✔️** Landed:

- `Widget.override` lease-on-construct for `St.Widget` + `Gjs_*` subclasses (`St-Widget.new` → `rpc_lid`); stock St leaves keep their own `St-* .new` constructs
- `st-widget-subclass-smoke.js`: Widget / UiActor / BoxLayout lease, construct `name`, `uiGroup.add_child(overviewGroup)` (+ `Clutter.BinLayout`) via **gjs-embed** + running `mutter-rpc`

**ℹ️** Product nested `gnome-shell-rpc` still dies in **libshell** `shell_global_attach_rpc_display` (`g_object_ref` / settings) before `layout.js` / `global.stage.add_child` — that wall is **[0.7.7](0.7.7-thin-shell-bootstrap.md)**, not more St lease hacks.
