## Purpose

0.6 is the **library** (mutter-shaped client `.so` + typelib). This plan is the **process** GJS runs in: an executable `**gnome-shell-rpc`** that does **not** start a compositor, loads **distro gnome-shell JavaScript** (package dependency), and talks Meta via `libmutter-rpc`.

**🔷** `✔️` `**mutter-rpc`** (compositor binary in this repo) **boots that shell** after the RPC socket is up — same polarity as [0.4](0.4-server-spawns-shell-client.md).

## Vendor ref: HEAD vs pin

**🔷** `⏳` Meson option controls which upstream revision `**scripts/gnome-shell-fetch.sh`** checks out into `**vendor/gnome-shell/**`.


| Mode               | Meson                                                                          | Who uses it                                                                                              |
| ------------------ | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| **HEAD** (default) | `-Dgnome_shell_vendor_ref=head` or unset                                       | **Nightly CI** (with refresh) — track upstream `main`. Local dev keeps last fetched tree unless refresh. |
| **Pin**            | `-Dgnome_shell_vendor_ref=48.0` (tag), `gnome-48` (branch), or full commit SHA | **Release / CI builds** — compile-time reference matches target distro gnome-shell version               |


**Add (meson options):**

```
option('gnome_shell_vendor_ref', type: 'string', value: 'head',
       description: 'Upstream gnome-shell ref when cloning or refreshing: head, tag, branch, or commit')

option('gnome_shell_vendor_refresh', type: 'boolean', value: false,
       description: 'If true, fetch/pull and checkout vendor ref; if false, use existing tree when present')
```

**ℹ️** `**gnome_shell_vendor_ref`** is the target revision for **clone** (first time) or **refresh** (explicit). It is **not** re-applied on every `meson setup` / `ninja` when a tree already exists.

## Vendor fetch: clone once, refresh on demand

**🔷** `⏳` `**scripts/gnome-shell-fetch.sh`** (or meson hook that calls it) follows this flow:


| State                             | `gnome_shell_vendor_refresh=false` (default)                | `gnome_shell_vendor_refresh=true`                                                 |
| --------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `**vendor/gnome-shell/` missing** | **Clone** shallow (or full) at `**gnome_shell_vendor_ref`** | Same — clone                                                                      |
| **Tree already present**          | **No network** — use checkout as-is; log current SHA        | `**git fetch`** + checkout ref (`main` + pull for `head`; tag/branch/SHA for pin) |


**ℹ️** **Local dev default:** one clone, then stable tree across rebuilds — no surprise upstream pulls mid-debug.

**🔷** **Nightly CI:** pass `**-Dgnome_shell_vendor_refresh=true`** (or env `**GNOME_SHELL_VENDOR_REFRESH=1**`) so each run exercises current upstream `**main**`.

**ℹ️** Manual refresh without reconfigure: `**./scripts/gnome-shell-fetch.sh --refresh`** (or `--refresh` + optional ref override) documented in `**gnome-shell/README.md**`.

**ℹ️** To switch ref locally: refresh with new `**-Dgnome_shell_vendor_ref=…`**, or delete `**vendor/gnome-shell/**` and configure again.

**ℹ️** Meson configure may run fetch **once** when vendor dir is missing; `**ninja`** must **not** hit the network unless refresh is on.

**ℹ️** Pin is **not** committed in git as a lockfile for day-to-day work — packaging passes it at **build time** (e.g. `debian/rules`: `meson setup … -Dgnome_shell_vendor_ref=48.0` to match `apt source gnome-shell`).

**ℹ️** When **HEAD** breaks us: fix in **our** code (client binary, `libmutter-rpc`, plugin) — not by shipping forked JS. When a **pinned release build** breaks: packaging / API mismatch with that distro `**gnome-shell`** version.

**ℹ️** Never hand-edit `**vendor/gnome-shell/`** — build-time snapshot only; fixes go in this repo’s code, not vendored JS.

**🔷** Nightly CI: `**gnome_shell_vendor_ref=head`** (default) **and** `**gnome_shell_vendor_refresh=true`** — no pin.

```
mutter-rpc --mutter-plugin gnome-shell-rpc.so
        │  listen RPC
        │  spawn ──────────────────────────────┐
        ▼                                      ▼
  compositor (real libmutter)         gnome-shell-rpc
                                        GJS + distro gnome-shell js/
                                        libmutter-rpc-16  (Meta-16.typelib)
```

## JavaScript: runtime from distro, not shipped

**🔷** Our `**.deb` / packages** ship `**mutter-rpc`**, `**gnome-shell-rpc**`, and `**libmutter-rpc**` — not upstream `**js/**`.


|                           |                                                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Runtime JS**            | From **installed `gnome-shell`** (`Depends:` / `Recommends:` in packaging). Client sets GJS `**search-path**` to the distro tree (pkg-config / known paths).                          |
| `**vendor/gnome-shell/**` | **Build / CI / dev** — reference upstream sources, nightly compatibility, future C/gresource compile if needed. **Not installed.**                                                    |
| **Touch JS?**             | **Prefer no** — no `meson install` of vendor or override JS, no bundling in packages. Exception only if bootstrap later proves impossible without a tiny, explicit, documented slice. |


**ℹ️** Nested dev on a machine with `**gnome-shell`** installed can use the **same distro JS path** as production; vendor checkout is optional for smokes that still use `**gjs-embed`** until Phase 3.

## Directory layout

Two top-level names — **vendor** (upstream snapshot) vs **gnome-shell** (our build layer):


| Path                      | In git?                                               | Role                                                                                                                         |
| ------------------------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `**vendor/gnome-shell/**` | **No** — listed in `.gitignore`; populated by `fetch` | Upstream checkout for **build / CI** — never commit, never hand-edit, **never install JS**.                                  |
| `**gnome-shell/**`        | **Yes**                                               | Meson integration, future **non-JS** client build glue if needed.                                                            |
| `src/gjs-embed/`          | **Yes** (temporary)                                   | **Test phase only** — minimal GJS host + smoke scripts; **deprecated** when `**gnome-shell-rpc`** uses distro JS (Phase 3+). |


**ℹ️** `**vendor/gnome-shell/` is gitignored** — Phase 1 adds `/vendor/gnome-shell/` to repo root `.gitignore`. Git tracks our integration under `**gnome-shell/`**, not upstream sources.

**ℹ️** HEAD may be ahead of a pinned release (e.g. mutter API 51 on `main` while Ubuntu ships 48.x). Nightly catches that drift; release builds pin the **vendor ref for compile checks**, while runtime JS still comes from the **distro `gnome-shell` package**.

**Add (repo root `.gitignore`):**

```
/vendor/gnome-shell/
```

**Add (tracked):**


| File                           | Role                                                                                |
| ------------------------------ | ----------------------------------------------------------------------------------- |
| `scripts/gnome-shell-fetch.sh` | Clone if missing; optional `**--refresh**` / meson `**gnome_shell_vendor_refresh**` |
| `gnome-shell/meson.build`      | Client-side targets only — does not build stock compositor `gnome-shell` binary     |
| `gnome-shell/README.md`        | HEAD vs pin; clone-once vs refresh; packaging passes pin at build time              |


**Add (root `meson.build`):** `subdir('gnome-shell')` after vendor presence is validated (or optional `-Dvendor_gnome_shell=disabled` for smokes-only builds).

## Phases

### Phase 1 — Vendor layout + fetch (no client boot yet)

**🔷** `✔️` Create `**gnome-shell/`** integration dir and `**vendor/gnome-shell/**` gitignore.

**Add:**

- `.gitignore` entry for `vendor/gnome-shell/`
- `scripts/gnome-shell-fetch.sh`, `gnome-shell/README.md`
- Meson options `**gnome_shell_vendor_ref**` (default `head`) and `**gnome_shell_vendor_refresh**` (default `false`)
- `gnome-shell/meson.build` stub: error if vendor missing and fetch disabled; run fetch on configure when dir absent

**Replace with:** nothing in `Rpc.Server` yet — still `gjs-embed` + smoke.

**ℹ️** `**fetch`** behaviour: missing dir → clone at ref; present + no refresh → no-op (print SHA); refresh → fetch + checkout ref. Log resolved SHA always.

**ℹ️** First nested proof for Phase 1: `meson setup` succeeds; first configure clones; second `ninja` does **not** re-fetch; `meson setup … -Dgnome_shell_vendor_refresh=true` updates tree.

**Exit:** **✔️** vendor tree fetchable at HEAD **and** at an explicit pin; integration dir tracked; vendor dir absent from git.

---

### Phase 2 — Meson: build-time vendor + runtime JS path

**🔷** `✔️` Wire `**gnome-shell/meson.build`**: **build-time** vendor variables; **runtime** path to **distro** gnome-shell JS (pkg-config or equivalent).

**Add:**

- Build-time only: `gnome_shell_vendor_root` → `vendor/gnome-shell/` (for CI / future C compile — **not installed**)
- Runtime: resolve `**gnome_shell_js_runtime_dir**` from `**gnome-shell` pc file** / install prefix (e.g. `sharedir/gnome-shell/js`) for `**gjs-embed`** / future `**gnome-shell-rpc**` `search-path`
- Meson override `**-Dgnome_shell_js_dir=**`; compile-time constant + `**GNOME_SHELL_JS_DIR**` env at runtime

**ℹ️** Do **not** invoke upstream gnome-shell’s full meson. Do **not** `install` vendor `**js/`** or any upstream JavaScript.

**Exit:** **✔️** client binary knows **distro JS path**; vendor vars available at compile time only; no JS installed by our meson.

---

### Phase 3 — `gnome-shell-rpc` shell binary + `mutter-rpc` compositor rename

**🔷** `✔️` Add product executable `**gnome-shell-rpc`** — GJS host that loads **distro gnome-shell JS**, not a rename-in-place of the test harness.

**Add:**

- Executable `**gnome-shell-rpc**` (may reuse embed guts from `**gjs-embed**` initially)
- **Rename** compositor executable `**gnome-shell-rpc`** → `**mutter-rpc**` (frees the short name for the shell)
- Default `**search-path**`: **installed gnome-shell `js/`** from Phase 2 (smokes / thin proof first — not `init.js` yet)

**Remove:** `**gjs-embed`** from the **product** spawn in `Rpc.Server` (keep `**gjs-embed`** + smokes behind test env / manual run until deprecated).

**Replace with:** spawn `**gnome-shell-rpc`** + `MUTTER_RPC_SOCKET`, `WAYLAND_DISPLAY`, `GI_TYPELIB_PATH`, `LD_LIBRARY_PATH` (bindir).

**Exit:** **✔️** nested `**mutter-rpc`** starts `**gnome-shell-rpc**` (not `**gjs-embed**`); shell is not the compositor; proof script or smoke still passes using **distro JS path**.
