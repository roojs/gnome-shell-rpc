## Three namespaces (naming)

| Layer | Vala namespace | Folder | Role | Example class names |
|-------|----------------|--------|------|---------------------|
| **Shared** | `GnomeShellRpc.Shared` | `src/shared/` | Generic `OLLMrpc.Bin.Serializable` value types — **no** `Meta.*`, **no** RPC handlers, **no** proxy logic. Same class in compositor, `rpc-client`, and fake shell. RPC object name is still **`Rectangle`**, not `Shared.Rectangle`. | `Rectangle` (more later if they stay generic) |
| **Server** | `GnomeShellRpc.Ui` | `src/ui/` | Entity snapshots + compositor-side `call_*` handlers. Registered with `OLLMrpc.Bin.register("Window", …)`. | `Window`, `Display`, `Workspace`, `*Params` |
| **Client / proxy** | `GnomeShellRpc.Remote` | `src/remote/` | Live GObject graph in any RPC client process (fake shell now; real shell later). Holds RPC **handle ids**, issues `RPC-*` calls, applies **notifications**. Class names are plain nouns — **`Window`**, not `RemoteWindow`. | `Window`, `Display`, `Session`, … |

**🚫** Do not prefix every client class with `Remote` (`RemoteWindow`, `RemoteDisplay`, …). The namespace is **`Remote`**; the type is **`Window`**.

**🚫** Do not duplicate shared types in `Remote` — decode RPC **results** with `Ui.Window` snapshots; use **`Shared.Rectangle`** (etc.) for embedded value fields on both sides.

### Shared `shared/` folder

**0.3 moves `Rectangle` out of `ui/` into `shared/`.** It is the first type that clearly belongs there: a generic serializable struct with no server or client behaviour.

- **`Remote.Window.frame_rect`** → `Shared.Rectangle?`
- **`Ui.Window.frame_rect`** → `Shared.Rectangle?` (field type changes; bin shape unchanged)
- **No `Remote.Rectangle`** — nothing to proxy; it is just a value field

**Rule of thumb for future types:**

| Put in `shared/` | Keep in `ui/` |
|------------------|---------------|
| Pure DTO, no `Meta.*`, compiled into every RPC binary | References `Meta.Display` / `Meta.Window` or owns `call_*` handlers |
| Same serialization on send and receive | Server-only registration side effects |

**Not moving in 0.3:** `Window`, `Workspace`, `*Params` stay under `Ui` — they are entity snapshots tied to the desktop API even though clients decode them. Revisit if more generic value types appear (colours, points, etc.) → add to `shared/` under the same rule.

**0.3 refactor (small):** `ui/Rectangle.vala` → `shared/Rectangle.vala` ✔️, namespace `GnomeShellRpc.Shared`.

## What this is (and is not) vs GNOME Shell

**The 0.3 GTK app is a fake shell — throwaway classes, not a permanent fixture, not the real shell.**

It exists only to prove: out-of-process chrome + one mutating RPC + crash/reconnect. Delete or replace it when the real shell lands.

| Piece | Keep? | Role |
|-------|-------|------|
| **`src/remote/`** (`Remote`) | **Yes — keeper** | Client library for the eventual real shell (and for this fake shell). Proxy objects over RPC. |
| **`src/fake-shell/`** (`FakeShell`) | **Throwaway** | Minimal GTK top bar: clock + Minimize. Not permanent. |
| Later real shell | Not in 0.3 | Full Vala (or other) shell UI — top bar, overview, hotkeys — consuming `Remote`. Separate plan. |

| Today (one process) | This project (0.3) |
|---------------------|---------------------|
| `gnome-shell` links `libmutter`, loads `libgnome-shell.so` as `MetaPlugin` | `gnome-shell-rpc` **is** the mutter plugin (compositor process) |
| GJS + Clutter `St.*` chrome on mutter’s **in-process** stage | Tiny Vala + GTK4 **fake shell** as a separate Wayland client |
| Top bar, overview, extensions, quick settings, … | **Clock strip + one Minimize button** only |
| Crash kills the session | Fake shell can `kill -9`; windows and compositor stay up |

**🚫** Do not name the throwaway `Shell` / `src/shell/` or `Panel` / `src/panel/`. Call it what it is: **`FakeShell`** / **`src/fake-shell/`**.

## Mutating window methods — no extra class

**0.2 `Ui.Window` is a snapshot** — title, rect, flags returned from `list_windows`. It is not a live `Meta.Window` and has no `call_*` handlers.

Mutations (`minimize`, `activate`, …) take a **handle id** and look up the leased `Meta.Window`. That logic belongs on **`Ui.Display`**, which already owns `Meta.Display` and all window queries:

- `call_minimize_window(WindowParams)` → resolve lease → `meta_window.minimize()`
- same for `unminimize`, `activate`, `close`

**Client API stays natural:** `Remote.Window.minimize()` — implementation sends `RPC-Display.minimize_window` (or similar) with `WindowParams.object_id`. No `WindowActions`, no second “Window” handler type.

**🚫** Do not add a contrived `WindowActions` / `WindowService` singleton just to match the `Window` RPC object name on the client.

---

Illustrative client shape (`Remote.Window.minimize` → `Display` RPC on the server):

```vala
namespace GnomeShellRpc.Remote {
    public class Window : GLib.Object {
        public int id { get; construct; }
        public string title { get; private set; default = ""; }
        public Session session { get; construct; }

        public signal void closed();

        public async void minimize() throws GLib.Error {
            yield this.session.display.minimize_window(this.id);
        }
    }
}
```

| Class | File | Responsibility |
|-------|------|----------------|

**0.3 minimum for exit:** `Session`, `Display`, `Window` (+ reuse `Ui.*` for entity decode, `Shared.Rectangle` for `frame_rect`).

**Not in `Remote`:** GTK widgets, layer-shell, clock label — those live under throwaway **`GnomeShellRpc.FakeShell`** (see below).

## Class inventory — server additions (`GnomeShellRpc.Ui` + `GnomeShellRpc.Rpc`)

Compositor-side changes only; **keep** existing RPC object names (`"Window"`, `"Display"`, …).

| Class / change | File | Responsibility |
|----------------|------|----------------|
| **`Window`** | `ui/Window.vala` | Unchanged **snapshot** type (serializable fields only). |
| **`Display` (extend)** | `ui/Display.vala` | Add mutating `call_*`: `minimize_window`, `unminimize_window`, `activate_window`, `close_window` — each takes `WindowParams` (`object_id`), resolves lease → `Meta.Window`, calls mutter API. Read-only queries unchanged (0.2). |
| **`WindowParams`** | `ui/WindowParams.vala` | Already exists — `object_id` for handle-targeted calls. |
| **`Server`** | `rpc/Server.vala` | No new registrations; `RPC-Display` handler already registered. |
| **`Plugin`** | `Plugin.vala` | Still retains `Rpc.Server` (0.2 lifecycle). |

RPC method examples:

- `RPC-Display.minimize_window` → `Display.call_minimize_window`
- `RPC-Display.list_windows` → unchanged (0.2)

**Plugin policy:** map / minimize / destroy **complete locally** in mutter (libdefault-style). RPC mutating methods change real window state; client is notified via existing handle notifications — **do not** block compositor on client ack.
