## Purpose

- **🔷** `⏳` **Override** path for Meta gaps that cannot use generic `Gi.convert` / generated `call_values` — foreign `Gio.*`, `GLib.Error`, streams, paired `Gio.Cancellable`.
- **🔷** `⏳` **Client:** real Meta stub signature (generated); **body** = injected Override text that forwards to the **helper RPC API** (not `Gi.dispatch`).
- **🔷** `⏳` **Server helper class** (e.g. `GnomeShellRpc.Meta.Helper`) — **delivers the missing API**. Each gap is a **complete RPC method** on the helper that implements what the typelib symbol would do if foreign types could cross the wire.
- **🔷** `⏳` **`CancellableBridge`** (own class, client + server) — register / id / twin / cancel replay. **Not** folded into `Meta.Helper`; helper methods take a `cancel_id` and call the bridge for the server-side `Gio.Cancellable`.
- **🚫** Do not invent Meta typelib symbols. Helper RPC names are **our** wire surface (`GnomeShellRpc.Meta.Helper.*` or similar), not fake entries on `Meta.*` in GIR.
- **🚫** Do not use the helper to **mini-patch** other paths — not a shared `file_from_uri` utility sprinkled into `Gi.dispatch`, generator fixes, or unrelated stubs. If it isn’t a listed missing-API gap, it doesn’t belong here.
- **🚫** Do not teach libocrpc to reconstruct arbitrary Gio GObjects for generic dispatch.

## Model (one picture)

```
JS / Vala stub API (real Meta name — generated signature only)
        │
        ▼
client Override body → Meta-Helper-SoundPlayer.…  (per-class wire prefix)
        │                    │
        │                    └── cancel_id arg (0 = none)
        ▼
CancellableBridge (client)          CancellableBridge (server)
  register(cancellable) → id    ←→    lookup(id) → twin Gio.Cancellable
  cancelled → cancel RPC              cancel RPC → twin.cancel()
        │
        ▼
SoundPlayer.Helper (server class) — delivers missing API for that Meta type
  — uses bridge for cancel_id; one helper class per overridden Meta type
```

| Path | Client | Server |
| --- | --- | --- |
| Normal Meta (leased) | generated `call_values` → `Meta-Window.…` | `Gi.dispatch` |
| **Missing API (this plan)** | `{Type}.override.vala` → **`Meta-Helper-{Type}.…`** | **`{Type}.Helper`** server class |

**ℹ️** Client stub keeps the **real Meta method name** for shell JS. Wire target is the per-class server helper RPC namespace.

**ℹ️** Today’s `Meta.overrides` (key=value, `list_elem=…`) stays for GIR lies. **Method bodies** come from **`--override-path`** files (below) — separate mechanism.

## Override files — one file per class (user)

### Client — inject at end of generated class

**🔷** `⏳` `gi-stub-gen` new flag: **`--override-path=DIR`**.

For each emitted class `SoundPlayer`, generator looks for:

```text
DIR/SoundPlayer.override.vala
```

If present: **append file contents inside the class**, after generated methods (before the closing `}`).

| | |
| --- | --- |
| File content | **Override methods only** — full Vala method bodies for gaps (replace `not_wired` / `GLib.error`) |
| Not in file | Class wrapper, namespace, usings — generator already emitted those |
| Naming | `{GIRTypeName}.override.vala` (e.g. `Background.override.vala`, `Context.override.vala`) |

**Example layout:**

```text
src/gi-stub/overrides/
  SoundPlayer.override.vala   # play_from_file, play_from_theme bodies
  Background.override.vala    # set_file body
  Context.override.vala       # terminate_with_error body
```

**Example `SoundPlayer.override.vala` (client — forwards to helper RPC):**

```vala
public void play_from_file(Gio.File file, string description, Gio.Cancellable? cancellable) {
    uint64 cancel_id = GiStub.CancellableBridge.register(cancellable);
    Runtime.call_values("Meta-Helper-SoundPlayer.play_from_file", this,
        OLLMrpc.args("sst", file?.get_uri() ?? "", description, cancel_id));
}
public void play_from_theme(string name, string description, Gio.Cancellable? cancellable) {
    …
}
```

**Generator behaviour:**

- Gap method with matching name in override file → **omit** generated `not_wired` stub; injected body wins.
- Override file exists but method missing → keep generated stub / gap report as today.
- **Add** `--override-path` to `gi-stub-gen` + meson `meta_window_generated` command when wiring build.

**🚫** Do not put override bodies in `Meta.overrides` key=value file — that file stays for metadata (`list_elem`, etc.).

### Server — one full helper class per Meta class

**🔷** `⏳` Server side is **hand-written Vala classes** (not injected). **One helper per Meta type** that has overrides.

```text
src/rpc/meta-helper/
  SoundPlayer.Helper.vala    # Request.register Meta-Helper-SoundPlayer.*
  Background.Helper.vala
  Context.Helper.vala
  CancellableBridge.vala     # cross-cutting — own class, not per Meta type
```

| Class | Registers (sketch) | Delivers |
| --- | --- | --- |
| `SoundPlayer.Helper` | `Meta-Helper-SoundPlayer.play_from_file`, … | mutter `Meta.SoundPlayer` |
| `Background.Helper` | `Meta-Helper-Background.set_file`, … | mutter `Meta.Background` |
| `Context.Helper` | `Meta-Helper-Context.terminate_with_error`, … | mutter `Meta.Context` |
| `CancellableBridge` | `RPC-Cancellable.*` | twin cancel only |

Each helper: `register_all()` on **itself**; boot eventually calls each — **not yet in Phase 1**.

**🔷** `⏳` Phase 1: write classes + compile in tree; **`🚫` no `Request.register` from `Server.start()`** until override inject + smoke are ready.

## CancellableBridge — own class (user)

**🔷** `⏳` Separate from **`Meta.Helper`**. Cross-cutting: any override (C1, C4, future async) that takes `Gio.Cancellable?` uses the same bridge — helper stays feature-focused.

| Side | Class (sketch) | Job |
| --- | --- | --- |
| **Client** | `GiStub.CancellableBridge` | `register(Gio.Cancellable?) → uint64` (0 = null); watch `cancelled` → send cancel RPC |
| **Server** | `Rpc.CancellableBridge` | `lookup(id) → Gio.Cancellable`; `cancel(id)`; drop id when call ends |
| **Wire** | e.g. `RPC-Cancellable.register` / `cancel` / `unregister` | Own class — not inside `SoundPlayer.Helper` |

**🚫** Phase 1: class exists; **not** registered in `Server.start()`.

```
client cancellable.cancel()
   → CancellableBridge.forward_cancel(id)
   → server CancellableBridge.cancel(id)
   → server twin.cancel()
   → mutter call aborts
```

**Why separate from Meta.Helper**

| | `Meta.Helper` | `CancellableBridge` |
| --- | --- | --- |
| Owns | Missing Meta feature RPC (sound, background, error, …) | Paired cancel lifecycle only |
| Reused by | Priority C override bodies | C1, C4, anything with `Cancellable?` |
| **🚫** | Cancel table / twin map | Meta / mutter calls |

**🔷** `⏳` Same live-id **family** as Remote / Callback? (**💩** start as dedicated bridge + small RPC prefix; fold into `Live.*` only if sign-off says one table.)

**🔷** `⏳` Volume slider smoke proves bridge + `Meta-Helper.play_from_file` together.

### C1 — SoundPlayer (first smoke)

```js
player.play_from_file(
    Gio.File.new_for_path(`${global.datadir}/sounds/device-added.oga`),
    _('External drive connected'),
    null);

this._volumeCancellable = new Gio.Cancellable();
player.play_from_file(
    Gio.File.new_for_path(`${global.datadir}/sounds/audio-volume-change.oga`),
    _('Volume changed'), this._volumeCancellable);
```

**Client — in `SoundPlayer.override.vala`:**

```vala
public void play_from_file(Gio.File file, string description, Gio.Cancellable? cancellable) {
    uint64 cancel_id = GiStub.CancellableBridge.register(cancellable);
    Runtime.call_values("Meta-Helper-SoundPlayer.play_from_file", this,
        OLLMrpc.args("sst", file?.get_uri() ?? "", description, cancel_id));
}
```

**Server — in `SoundPlayer.Helper.vala`:**

```vala
void play_from_file(Meta.SoundPlayer player, string uri, string description, uint64 cancel_id) {
    var file = uri != "" ? Gio.File.new_for_uri(uri) : null;
    var cancel = Rpc.CancellableBridge.lookup(cancel_id);
    player.play_from_file(file, description, cancel);
}
```
