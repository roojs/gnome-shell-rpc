## What gets exported over RPC (plain English)

Mutter’s real objects (`MetaWindow`, `MetaDisplay`, `MetaWorkspace`, …) live **inside the compositor process**. They are C/GObjects tied to the stage; you cannot memcpy them onto a Unix socket.

The out-of-process client only ever sees **binary RPC frames** (`OLLMrpc.Bin`). So this repo defines its own small Vala classes — **`Display`**, **`Window`**, **`Workspace`**, etc. — that:

1. **Describe compositor state in client-safe terms** — e.g. window title, whether it is minimized, frame rectangle. A snapshot the shell can show or cache, not a live pointer into mutter.
2. **Implement the RPC contract** — `Bin.Serializable`, registered with `OLLMrpc.Bin.register`, plus `call_*` handlers for methods like `Display.list_windows` (same pattern as ollmfilesd’s `File` / `Folder`, which are also daemon-local types, not generic libocrpc).
3. **Are filled in from mutter when something happens** — on `window-created`, the server reads `MetaWindow`, builds a `Window` snapshot (or exports a handle and notifies with `Notification.id`), and writes that on the socket.

So there are **two layers**:

- **`src/rpc/`** — socket listener, connections, hello, broadcasting notifications.
- **`src/ui/`** — **`GnomeShellRpc.Ui`**: the **remote representation of what the user sees** — windows, workspaces, focus. Serializable snapshots + method handlers that read mutter and reply. Not raw `Meta*`. Not GTK widgets (those live in the out-of-process shell client in **0.3**); this is the **model** the client uses to know what is on screen.

**🚫** Do not auto-serialize every `Meta*` type. Only this curated set.

**✅** Folder **`src/ui/`**, Vala namespace **`GnomeShellRpc.Ui`** — user choice (Aug 2026).

### Server — `src/ui/` (`GnomeShellRpc.Ui`)

Remote **representation of desktop state** — what the user would see (windows, workspaces, focus), encoded for RPC. Serializable **`Display` / `Window` / `Workspace`** classes + method param types. Each class reads mutter and answers RPC calls; each snapshot encodes its properties for the client.

- **`src/ui/namespace.vala`** — `GnomeShellRpc.Ui` namespace doc
- **`src/ui/Rectangle.vala`** — serializable stand-in for `Meta.Rectangle` (custom `bin_write_prop` / `bin_read_prop`)
- **`src/ui/Window.vala`** — window as the client sees it: handle `id`, `title`, `wm_class`, `minimized`, `maximized`, `frame_rect`; built from `MetaWindow`; read-only in 0.2
- **`src/ui/WindowParams.vala`** — arguments for “get window by handle id”
- **`src/ui/Workspace.vala`** — workspace snapshot: `id`, `index`, window ids; built from `MetaWorkspace`
- **`src/ui/WorkspaceParams.vala`** — arguments for workspace lookups (minimal first cut)
- **`src/ui/Display.vala`** — display RPC methods: `list_windows`, `get_window`, focused window id, workspace count; backed by `MetaDisplay`
- **`src/ui/DisplayParams.vala`** — arguments for display methods

**Server behaviour** (in `Server.vala` + `ui/Display.vala`):

- **`window-created`** → `connection.export(meta_window)` → `Notification { method = "Window.created", object_type = "Window", id = … }`
- **window unmanaged** → `Window.closed` notification; handle retired on connection lifecycle
- **`notify::title`** → interim notification with `id` + property in `message` until **8.3.2** subscribe lands

### Lifecycle (learned in implementation)

**🔷 CRITICAL:** GObject refs must outlive the main loop and any socket IO watches.

- **Compositor:** `Plugin` must **retain** `Rpc.Server` (field `rpc_server`). `new Rpc.Server().start(display)` without retention collected the server immediately → socket file existed but accepts failed / broken pipe on hello.
- **Test client:** `Main` must **retain** `OLLMrpc.Client` (static `rpc_client`). Local `var client` in `run()` was destroyed when the async method returned while `MainLoop` still ran → segfault on notifications.

### libocrpc client boot (decoupled)

- **`OLLMrpc.Client.connect(hello, boot)`** — pass **`ClientBoot`** to spawn/wait for ollmfilesd; pass **`null`** (omit second arg) to attach to an already-listening socket (gnome-shell-rpc compositor).
- **🚫** Do not use default ollmfilesd boot against `mutter-rpc.sock` — `ClientBoot.ensure_daemon()` may unlink the socket and spawn `ollmfilesd`.

## Tasks — export surface (read-only)

- **Display** — focused window id, workspace count
- **Window** — handle id, title, wm-class, minimized, maximized, frame rect
- **Workspace** — id, index, window ids

Server behaviour:

- **🔷** `✔️` On `window-created` / dispose: `export()` / retire handle; push notification:

```vala
connection.write(new OLLMrpc.Notification() {
    method = "Window.created",
    object_type = "Window",
    id = (int) connection.export(meta_window)
});
```
