## Purpose

- **🔷** Split today’s in-process `gnome-shell` + `libmutter` blob into two processes.
- **🔷** Mutter stays a **standalone Wayland compositor**. This plugin **receives** method calls and **streams** GObject state over a Unix-domain socket.
- **🔷** The shell (later `0.2`) becomes a **Vala RPC client** that can crash, restart, and upgrade without taking the compositor or app surfaces with it.
- **🔷** Reuse OLLMchat’s GObject-native binary RPC (`libocrpc`) instead of inventing JSON/D-Bus bindings for hundreds of Mutter classes.
- **🔷** Each phase yields a **bootable, nested, testable** binary. No “big bang” cutover.

```
  today (one process)                    target (two processes)
  -------------------                    ----------------------
  gnome-shell binary                     mutter binary
    links libmutter.so                     DRM/KMS, Wayland, Meta*
    loads libgnome-shell.so  ← plugin      gnome-shell-rpc .so  ← plugin
    GJS panels on Clutter stage              starts SocketListen
    crash = session death                    completes map/minimize locally
                                             (never waits on the client)
                                                      ▲
                                                      │ AF_UNIX bin frames
                                                      ▼
                                             Vala shell (separate process)
                                               RPC client, GTK4 chrome
                                               normal Wayland surface
                                               kill -9 → windows stay
```

## Current behaviour (stock mutter)

- **ℹ️** Distro `mutter` defaults `--mutter-plugin` to `libdefault`. It does **not** load `libgnome-shell.so`.
- **ℹ️** `meta_context_setup()` fatals only if **no** plugin name **and** no plugin `GType` is set. Standalone mutter is already a thing.
- **ℹ️** Nested run is **`--wayland --devkit`**, not `--nested`.
- **ℹ️** `MetaScreen` is gone. Window/workspace APIs hang off `MetaDisplay`, `MetaWorkspaceManager`, `MetaMonitorManager`.
- **ℹ️** GNOME Shell is the process that **links `libmutter`** and installs itself as the compositor plugin. That is the in-process coupling we are cutting.
- **ℹ️** `MetaPlugin` vfuncs (`minimize`, `map`, `destroy`, `switch_workspace`, …) are how the shell currently owns animations **inside** the compositor process. Reference: mutter `src/meta/meta-plugin.h`.

## How it glues together (plugin vs RPC vs shell)

Gemini did **not** invent the plugin slot. Mutter **will not start** without one (`"No compositor plugin set"`). The original write-up skipped that and hung the socket off `main.c`. Both can be true: the plugin is mandatory compositor glue; the RPC socket is how an **out-of-process** shell talks.

### Today

- **ℹ️** There is no “mutter daemon + gnome-shell client”. **GNOME Shell is the process.** It links `libmutter`, calls `meta_context_set_plugin_name("libgnome-shell")`, and runs GJS on the **same** GLib loop and **same** Clutter stage as the window actors.
- **ℹ️** `libgnome-shell.so` **is** the `MetaPlugin`. Map / minimize / overview / panel are in-process Clutter on mutter’s stage. One crash kills the session.

### What a plugin actually is

A `MetaPlugin` is not a generic “module”. It is the compositor’s **effect and chrome hook**:

- `start` — compositor is up; gnome-shell currently builds its UI here
- `map` / `minimize` / `destroy` / `switch_workspace` — mutter pauses that window’s transition until the plugin calls completed
- `keybinding_filter`, `show_window_menu`, `confirm_display_change`, force-quit dialogs

`libdefault` is the built-in implementation of those vfuncs: short Clutter tweens, then complete. That is why `mutter --wayland --devkit` already works with no gnome-shell.

### Is “the plugin is the RPC gateway” feasible?

**Yes.** It is the natural slot. It was not rejected.

| Piece | Process | Role |
| --- | --- | --- |
| `RpcPlugin` (`MetaPlugin`) | mutter | In-process: complete effects locally; **notify** the client; `start()` opens `SocketListen` |
| `libocrpc` socket | mutter (inside the plugin) | Method calls in (`Window.minimize`); signals/properties out |
| Vala shell | **other** process | GTK4 panel / overview as a normal Wayland client. **Not** a mutter plugin |

- **🔷** Put the listener in `RpcPlugin.start()` — same place gnome-shell currently starts UI, and the plugin already has `meta_plugin_get_display()`.
- **🔷** Plugin vfuncs **fire-and-forget notify** the client, then complete the mutter-side effect themselves (copy `libdefault` behaviour).
- **🚫** Do **not** wait for the remote shell to call “effect completed”. If the client is dead, windows would never map. That is the silly version; that is what this plan rejects.
- **🚫** The Vala shell is **not** loaded with `--mutter-plugin`. It is a Wayland client + RPC client.

Phase 1 can keep stock `libdefault` (no socket yet). Phase 2 loads **this repo’s** `.so` = `libdefault` animations + socket + export. No need to hang a second listener off mutter `main.c`.

### Two event paths (both real)

- **Display GObject signals** (`window-created`, `notify::title`, …) — good for state sync. RPC exports these regardless.
- **Plugin vfuncs** (`map`, `minimize`, `destroy`, …) — mutter will not emit those as ordinary signals; they only go through `MetaPluginClass`. If we want the client to know “this window is mapping now”, the plugin must forward them. That is why the gateway **is** a plugin, not only a socket in mutter `main.c`.

## Why Vala + `libocrpc` (not a new protocol)

- **🔷** Vala compiles to GObject C. Signals, properties, and refcounting are syntax, not bindings.
- **🔷** `OLLMrpc.Bin` already encodes GObject properties as compact binary frames keyed by `GLib.Type` fundamentals. Nested objects, `G_TYPE_VARIANT`, and boxed overrides exist.
- **🔷** Server dispatch is `Object.method` → signal on a registered handler singleton (`OLLMrpc.Request`). Notifications have no matching response id (`OLLMrpc.Notification`).
- **🔷** Unix socket listener already exists: `OLLMrpc.Transport.SocketListen`.
- **🚫** Do not auto-proxy every live `MetaWindow` C instance as if GJS could not tell. Export a **curated** wire surface (`Display`, `Window`, `Workspace`, …) registered with `OLLMrpc.Bin.register`, same pattern as OLLMchat `File` / `Folder`.
- **🚫** Do not put GTK in the plugin / mutter process.

### What `libocrpc` already gives us vs what OLLMchat `8.3` adds

- **ℹ️** Already in OLLMchat: property encode/decode, `Request` / `Response` / `Notification`, per-connection name tokens, `SocketListen`, `Object.method` dispatch, async `yield client.call`.
- **🔷** `⏳` Live `uint64` handles, `RemoteUnref`, subscribe, typed notification payload, `SCM_RIGHTS` — **OLLMchat plan `8.3`**. Do not invent a parallel protocol here.
- **🔷** `⏳` This repo: `MetaRectangle` / colour DTOs via existing `bin_write_prop` overrides. Plugin-event `Notification`s (`map`, `minimize`) after local complete. Not `libocrpc` core.

## Architecture (plugin = receiver)

1. **Host (`mutter` process):** DRM/KMS, Wayland surfaces, Clutter stage. Phase 1 uses stock `libdefault`. Phase 2+ loads this plugin (same animations as `libdefault`, plus `SocketListen` in `start()`).
2. **IPC:** `AF_UNIX` socket, `OLLMrpc.Bin` frames. Path e.g. `$XDG_RUNTIME_DIR/mutter-rpc.sock` (overridable).
3. **Handles:** when Mutter creates a `MetaWindow` / `MetaWorkspace`, the plugin assigns a `uint64` ipc id and holds a GObject ref until the client `RemoteUnref`s (or the connection drops).
4. **Client (plan `0.2`):** Vala process in this repo. Builds local proxy GObjects from handles, GTK4/libadwaita chrome. Not GJS for the first client — GJS-shaped proxies are a later optional consumer of the same socket.

### GObject behaviours the RPC must honour

#### Remote reference counting

- **ℹ️** Contract lives in OLLMchat **`8.3` Phase 1**. This plugin is a consumer: lease `MetaWindow` / `MetaWorkspace`, never destroy a window because the client unref’d a proxy.

#### `GValue` / boxed serialization

- **ℹ️** Scalars and `GVariant` follow `libocrpc` defaults.
- **🔷** `⏳` Custom `bin_write_prop` / `bin_read_prop` **in this repo** for Mutter boxed structs on the exported API (`MetaRectangle`, `cairo_rectangle_int_t`, colour types).
- **ℹ️** Dmabuf fds: OLLMchat **`8.3` Phase 4**. This repo must not dump Cogl textures as pixel blobs.

#### Sync vs async returns

- **ℹ️** `yield client.call` is already the OLLMchat client API. No `call_sync` here.

## Phase 2 — RPC server + read-only event streaming

**Goal:** This plugin listens on a Unix socket. Export read-only `Display` / `Window` / `Workspace`. Zero frame drops while a test client listens.

### Tasks — vendor `libocrpc`

- **🔷** `⏳` Copy / wrap OLLMchat `libocrpc` into this repo (subproject). Keep the `OLLMrpc` namespace until a rename is an explicit follow-on.
- **🔷** `⏳` Meson: Vala + gee-0.8 + gio-unix + `libmutter-16`. Build a `shared_module` plugin `.so`.
- **🚫** Do not pull GTK, `libollmchat`, or `ollmfilesd` into the plugin.

### Tasks — listener

- **🔷** `⏳` `RpcPlugin`: keep the existing local map/minimize/destroy tweens (`libdefault` behaviour), and in `start()` open `OLLMrpc.Transport.SocketListen` on the GLib default main context. Socket path from env `MUTTER_RPC_SOCKET` with a runtime-dir default.
- **🔷** `⏳` Load with `mutter --mutter-plugin /abs/path/to/the.so` (absolute path; no install into mutter’s plugin dir).
- **🔷** `⏳` `Daemon.hello` (same idea as ollmfilesd) so a client can handshake and dump protocol version.

### Tasks — export surface (read-only)

Wire types (names are indicative):

| Wire alias | Server object | First properties |
| --- | --- | --- |
| `Display` | `MetaDisplay` | `id`, focused window id, workspace count |
| `Window` | `MetaWindow` | `id`, `title`, `wm-class`, `minimized`, `maximized`, frame rect |
| `Workspace` | `MetaWorkspace` | `id`, index, window ids |

- **🔷** `⏳` On `window-created` / window disposed: assign / retire handles; send `Notification` (`Window.created`, `Window.closed`).
- **🔷** `⏳` Generic `notify` on exported objects → `Notification` with property name + value (shadow cache on the client).
- **🔷** `⏳` `Display.list_windows` / `Display.get_window` request → array of `Window` snapshots (ids + current props). Reconnect must be able to rebuild state from this.

### Tasks — test client (not the shell yet)

- **🔷** `⏳` Standalone Vala tool in this repo: connect, print `Window.created` / `title` changes.
- **🔷** `⏳` Nested mutter + test client + `gedit`. Confirm compositor still paints; no obvious frame-clock stalls (qualitative first; add a counter later if we care).

### Exit

- Socket exists while nested mutter runs with our plugin.
- Test client sees window create/title/close for apps on that display.
- Killing the test client does **not** kill mutter or the nested `gedit`.

## Phase 3 — Out-of-process “minimal shell” (top bar)

**Goal:** First UI **outside** mutter. A Vala process renders a panel as a Wayland surface and calls one mutating method.

**ℹ️** Detailed client layout is **plan `0.2`**. This phase only fixes the **server** contract the client needs.

### Server tasks (this plan)

- **🔷** `⏳` Mutating methods: `Window.minimize`, `Window.unminimize`, `Window.activate`, `Window.close` — dispatched on the server, executed on the real `MetaWindow`.
- **🔷** `⏳` `RpcPlugin` still completes effects locally (same as `libdefault`). Notify the client; **do not** block waiting for it to “complete” an animation.
- **🔷** `⏳` Layer-shell (or equivalent) so the client panel is a normal Wayland surface mutter already composites. Prefer an existing protocol mutter implements over inventing subsurfaces.

### Client tasks (land in `0.2`, sketched here)

- **🔷** `⏳` Minimal Vala app: connect to `MUTTER_RPC_SOCKET`, subscribe, draw a top clock/status bar (GTK4).
- **🔷** `⏳` One button → `Window.minimize` on the focused window id.
- **🚫** Do not load GNOME Shell extensions in Phase 3.
- **🚫** Do not rewrite gnome-shell JS in this phase.

### Exit

- Nested: mutter + Vala panel + `gedit`.
- Click in the panel changes window state in mutter.
- `kill -9` the **panel process** → nested `gedit` stays interactive; mutter window stays open.

## Phase 4 — Input delegation, hotkeys, overview

**Goal:** Interactive desktop bits that today live in the in-process plugin.

### Tasks

- **🔷** `⏳` **Hotkeys:** register global keybindings over RPC (`Super` → client toggles overview). Mutter grabs keys; client decides policy.
- **🔷** `⏳` **Overview previews:** pass **dmabuf fds** (or a mutter-owned thumbnail protocol) so the client can composite thumbnails without owning Cogl textures.
- **🔷** `⏳` **Plugin events:** `RpcPlugin` forwards `map` / `destroy` / `switch_workspace` as notifications so the client can animate **its** actors. Mutter still owns the real window actors and completes mutter-side effects without waiting on the client.
- **💩** `⏳` Extensions load **only** in the client process, talking solely to proxy GObjects. Confirm in `0.2` whether extensions stay GJS or we drop them for the Vala shell.

### Risks

- **💩** Overview is the hard IPC problem. Pixel copies will miss frame budget. Design fds first.
- **💩** `keybinding_filter` today is an in-process vfunc. A round trip per key is too slow — grab list is configured up front; mutter matches locally and notifies.

### Exit

- Super opens/closes a client-side overview stub.
- Nested apps keep receiving input while the client overview is up (policy TBD: grab vs pass-through).

## Follow-on (`0.2`) — Vala shell client

Not implemented in this plan. Sketch so the server surface stays honest:

- **🔷** Transmitter / client: connect, subscribe, keep a shadow object graph, render chrome.
- **🔷** Sync on reconnect (crash recovery is a **client** problem plus `list_windows`).
- **🔷** GTK4 / libadwaita panels. Optional later: GJS talking to the same proxies via GI.
- **ℹ️** Default home for the client is this repo (`shell/` or similar). Split only if it gets huge.

Example of the proxy shape (illustrative, not a code fence to paste):

```vala
public class RemoteWindow : GLib.Object {
    public uint64 object_id { get; construct; }
    public string title { get; set; default = ""; }
    public bool is_maximized { get; set; default = false; }

    public signal void closed();

    public async void minimize() throws GLib.Error {
        yield RpcBridge.call(this.object_id, "minimize");
    }
}
```
