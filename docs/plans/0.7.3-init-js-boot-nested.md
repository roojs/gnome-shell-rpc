## Purpose

Run distro (or vendor-pinned) **`js/ui/init.js`** in nested **`mutter-rpc`** + **`gnome-shell-rpc`**, then grow toward **`main.js`** / chrome. After a boot path exists, add nightly HEAD CI and release-pin docs.

**ℹ️** **Not** “point `gnome-shell-rpc` at `init.js` and go.” Stock `init.js` assumes monolithic gnome-shell (C already called `_shell_global_init()`, then JS runs `global.context.run_main_loop()` in-process). Our split keeps the compositor in **`mutter-rpc`** — bridge that in **our** host code; **🚫** do not fork upstream JS into packages.

**Gap-fix:** same as 0.7 — fix blockers in this repo (stubs, Helpers, host). JS overrides last resort with explicit approval.

**ℹ️** Already landed toward row 7: stock **`Meta-16.typelib`**; **0.7.1 Phase 2** scaling **✔️**; `Meta.Background` + lease-in-`args`; `gsr-lease-id` as uint64 qdata; nested `bg-subclass-smoke` **ok**. **`ShellGLSLEffect`:** fixed via C effect parents (`c-clutter-effect-abi.c`); same pattern is the starting point for **0.7.5** Actor.

**ℹ️** **Current wall:** fix-forward nested `init.js` (e.g. missing C symbols). Actor class −8 (`parent_set`) **✔️**.

**ℹ️** **Struct constructors:** generator emits `malloc0` stubs (`struct_ctor_alloc_stub` in `Clutter_generated.missing.md`). **Audit** against stock — if a ctor does more than allocate, implement it when boot needs that behaviour.

**ℹ️** **`misc/config.js` — generate, do not copy.** Upstream ships only `js/misc/config.js.in` (`@PACKAGE_VERSION@`, `@LIBMUTTER_API_VERSION@`, `@HAVE_NETWORKMANAGER@`, folder-app lists, `datadir` / `libexecdir`). Stock gnome-shell meson substitutes those at build time and embeds the result in **gresource** (`resource:///org/gnome/shell/misc/config.js`). There is no finished source file to copy; a file under `vendor/…/misc/config.js` is leftover build output. Distro packages often ship JS **only** in gresource (no `/usr/share/gnome-shell/js/`). Our client default is the same resource tree via `libshell`’s `js-resources` — `gnome-shell/client-libs/shell-js/` runs the same `configure_file` and puts the build dir **first** on `compile_resources` `source_dir`. **🚫** `meson install` of that file into the distro JS tree.

**Exit:** nested client evaluates **`init.js`** (or agreed thin subset) without forking upstream JS; compositor remains **`mutter-rpc`** only.

## Phase B — Upstream compatibility CI + release pin

**🔷** `⏳` **After** Phase A has a boot path worth regressing.

**Nightly (HEAD + refresh):**

- Scheduled Actions: `meson setup … -Dgnome_shell_vendor_refresh=true` → build → nested tests (smokes minimum; `init.js` once Phase A green)
- Fail the job on build/test failure against current `main` HEAD
- **ℹ️** Nightly does not produce packages

**Release / distro packages (pin + Depends):**

- `-Dgnome_shell_vendor_ref=<tag>` on clean builders aligned with target distro sources
- Package `Depends: gnome-shell` — **no** bundled `js/`
- Pin lives in packaging, not repo HEAD-by-default workflow

**Exit:** nightly on HEAD (red = actionable); documented pin example for one distro; release path uses `-Dgnome_shell_vendor_ref=…`.
