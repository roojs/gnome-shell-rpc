# 1.2 — Teardown, restart, and a fallback while the shell is down

**User goal:** when the client goes away, remove the actors registered for that session. Then restart the client, with extensions off. If that restart fails, unminimize every application window and move those windows onto the workspace already on screen, so the user can save and close them, then restart the server and the desktop.

Checklist: `docs/guide-to-writing-plans.md`.

**Status:** **ACTIVE** — user 2026-10-03. Nested prove. No greeter install.

- **🔷** `✔️` Client gone: disconnect the signals and the other registrations for that session, then remove the actors. Nested 2026-10-03: the server survives a client kill.
- **🔷** `✔️` As soon as that teardown finishes, restart the client. Extensions off. Nested 2026-10-03: `client exited ready=true`, new `gsr-client` spawned, `GNOME Shell started` again.
- **🔷** `⏳` If that restart fails, unminimize every application window and move those windows onto the workspace already on screen. The user saves and closes them, then restarts the server and the desktop.
- **💩** “Session” in the fences is that client’s RPC connection: actors, keybindings, grabs, barriers, and signal handlers leased on it. Application windows stay so the work can be saved.
- **ℹ️** `spawn_client()` does not watch the child (`src/server/rpc/Server.vala`). `Gsr.Server.Rpc.Connection.stopped` fires once from `stop()`, **after** `base.stop()`.
- **ℹ️** `Listen.connections` never drops a stopped connection. Only `Listen.stop()` clears it.
- **🚫** Destroying `Meta.Window` or `Meta.WindowActor`. **🚫** A window list, an activate button per window, or any other chrome stand-in. **🚫** Another GJS process. **🚫** Vendor `js/`.

**💩** Restart only when the client that died had reached `notify_ready` (its connection has `ready` set). A client that never reached ready is not spawned again; the windows are gathered instead. That covers a failed restart and a failed first boot the same way.

**💩** A client still not ready 30 seconds after spawn is killed with `force_exit`. Its exit then goes down the same wait path as any other.

Named for the coding-standards gate (do not add others):

- field on `Gsr.Server.Rpc.Server`: `client_proc`
- fields on `Gsr.Server.Rpc.Connection`: `session_leases`, `ready`; signal `stopping`
- class `Gsr.Server.Rpc.Lease`

#### Replace with — `spawn_client` `spawnv`, debug line, ready timeout, and wait

The debug line stays. The wait callback owns the restart decision, and its tail is the give-up in section 3. A wait or timeout for an older process does nothing, because a restart has already replaced `client_proc`.

```vala
				var proc = this.smoke_client.spawnv(this.display, argv);
				this.client_proc = proc;
				GLib.debug(
					"spawned %s pid=%s MUTTER_RPC_SOCKET=%s WAYLAND_DISPLAY=%s via global::Meta.WaylandClient",
					string.joinv(" ", argv),
					proc.get_identifier().to_string(),
					this.rpc_socket_path,
					wayland_display ?? "(unset)"
				);
				GLib.Timeout.add_seconds(30, () => {
					if (this.client_proc != proc) {
						return GLib.Source.REMOVE;
					}
					foreach (var connection in this.listen.connections) {
						if (((Gsr.Server.Rpc.Connection) connection).ready) {
							return GLib.Source.REMOVE;
						}
					}
					proc.force_exit();
					return GLib.Source.REMOVE;
				});
				proc.wait_async.begin(null, (obj, res) => {
					try {
						proc.wait_async.end(res);
					} catch (GLib.Error e) {
						GLib.warning("client wait: %s", e.message);
					}
					if (this.client_proc != proc) {
						return;
					}
					this.client_proc = null;
					var was_ready = false;
					foreach (var connection in this.listen.connections.to_array()) {
						was_ready |= ((Gsr.Server.Rpc.Connection) connection).ready;
						connection.stop();
					}
					this.listen.connections.clear();
					if (was_ready) {
						this.spawn_client();
						if (this.client_proc != null) {
							return;
						}
					}
					var mgr = this.display.get_workspace_manager();
					var workspace = mgr.get_active_workspace() ?? mgr.get_workspace_by_index(0);
					if (workspace == null) {
						return;
					}
					foreach (unowned global::Meta.Window window in this.display.list_all_windows()) {
						var type = window.get_window_type();
						if (window.is_override_redirect()
							|| type == global::Meta.WindowType.DESKTOP
							|| type == global::Meta.WindowType.DOCK) {
							continue;
						}
						if (!window.is_on_all_workspaces() && window.get_workspace() != workspace) {
							window.change_workspace(workspace);
						}
						if (window.minimized) {
							window.unminimize();
						}
					}
				});
```

## 2. Teardown

**💩** `✔️` Cleanup lives in destructors and in two lambdas in `connection_ready`. No Server method. Order is fixed by `Connection.stop()`:

1. `stopping` lambda: clear each actor's `vfuncs`. Copy into a local list the leased actors that sit directly on the stage or in `window_group` (that holds a ref).
2. `Connection.stop()` clears `session_leases` (destructors undo them), then `base.stop()` (libocrpc) disconnects every `signal_subs` handler and unrefs `leases`.
3. `stopped` lambda: put `window_group`, `top_window_group`, and the feedback group back on the stage, as stock `layout.js` does on `shutdown`. Then destroy the copied actors. Every handler is already gone, so `destroy()` emits to nobody.

**ℹ️** `Connection.vala` is also built into `gi-rpc-echo` and the `call-sync-repro` gates, which have no mutter. So `Connection` cannot name `Meta`, `Clutter`, or `Lease`. `session_leases` is typed `GLib.Object`, and the actor work is in `Server.vala`.

**ℹ️** 2026-10-03 nested: the first try destroyed every leased actor except window actors and the stage. That destroyed `window_group`, which the client leases and the shell has reparented into `uiGroup`, and mutter then segfaulted in a stage signal handler. Rescuing the three mutter groups first, and destroying only the stage's and `window_group`'s direct leased children, fixed it.

**💩** `⏳` Hooks on layout managers and constraints, and a client dying mid-message: [`1.2.1-teardown-followups.md`](1.2.1-teardown-followups.md) §1 and §2.

**ℹ️** `⏳` After give-up the leftover panel and dash stay on screen: [`1.2.1-teardown-followups.md`](1.2.1-teardown-followups.md) §3.

**ℹ️** `signal_subs` disconnect stays in libocrpc `stop()`. A `~Subscription` destructor would be an OLLMchat change, and the `notify::` handler closure holds the `Subscription`, so that destructor would not run.

**ℹ️** Not in `signal_subs` today, ids thrown away:

- `Keybinding.add_keybinding` / `keybindings_set_custom_handler` — mutter keeps the binding.
- `ClutterActor.add_hook` — `key_press_event.connect` / `key_release_event.connect` return value ignored.
- `Actor.vfuncs` — `Live.Hook` on the actor. `destroy` during layout calls it.

**💩** Leases hold the stage, the window groups, and other actors mutter owns. Only actors this client created may be destroyed. The stage-and-`window_group`-children rule stands in for that. A leased actor that is not parented there is left to the lease unref.

#### Add — `src/server/rpc/Lease.vala`

New file. Add `'server/rpc/Lease.vala',` after `'server/rpc/Connection.vala',` in the `gsr-server` source list in `src/meson.build` (line 12) only. `gi-rpc-echo` (line 288) has no mutter.

**💩** `⏳` One class. The destructor picks the undo from the target type. Weak on the target so the lease does not keep it alive.

```vala
namespace Gsr.Server.Rpc
{
	/**
	 * Something one client connection registered on the server.
	 * Dropping the lease undoes it.
	 *
	 * - {@link global::Meta.Display} + name: add_keybinding
	 * - null target + name: keybindings_set_custom_handler
	 * - any other object + hid: a signal handler
	 */
	public class Lease : GLib.Object
	{
		private GLib.WeakRef target;
		private bool has_target;
		private string name;
		private ulong hid;

		public Lease(GLib.Object? target, string name = "", ulong hid = 0)
		{
			this.target = GLib.WeakRef(target);
			this.has_target = target != null;
			this.name = name;
			this.hid = hid;
		}

		~Lease()
		{
			if (!this.has_target) {
				global::Meta.KeyBinding.set_custom_handler(this.name, null);
				return;
			}
			var live = this.target.get();
			if (live == null) {
				return;
			}
			if (live is global::Meta.Display) {
				((global::Meta.Display) live).remove_keybinding(this.name);
				return;
			}
			if (this.hid != 0) {
				GLib.SignalHandler.disconnect(live, this.hid);
			}
		}
	}
}
```

```vala
			this.listen.connection_ready.connect((connection) => {
				foreach (var view in stage.peek_stage_views()) {
					connection.export(view);
				}
				/* Stock layout.js shutdown: the shell reparents these mutter
				 * groups into uiGroup. Put them back on the stage before
				 * destroying the shell's actors, or they die with uiGroup. */
				var compositor = this.display.get_compositor();
				global::Clutter.Actor[] adopted = {
					compositor.get_window_group(),
					compositor.get_top_window_group(),
					compositor.get_feedback_group(),
				};
				var doomed = new Gee.ArrayList<global::Clutter.Actor>();
				var conn = (Gsr.Server.Rpc.Connection) connection;
				conn.stopping.connect((c) => {
					foreach (var lease in c.leases.values) {
						var hooked = lease as Gsr.Server.Clutter.Actor;
						if (hooked != null) {
							hooked.vfuncs.clear();
						}
						var actor = lease as global::Clutter.Actor;
						if (actor == null
							|| actor is global::Meta.WindowActor
							|| actor in adopted) {
							continue;
						}
						var parent = actor.get_parent();
						if (parent == stage || parent == adopted[0]) {
							doomed.add(actor);
						}
					}
				});
				conn.stopped.connect(() => {
					foreach (var group in adopted) {
						var parent = group.get_parent();
						if (parent == stage) {
							continue;
						}
						if (parent != null) {
							parent.remove_child(group);
						}
						stage.add_child(group);
					}
					foreach (var actor in doomed) {
						actor.destroy();
					}
					doomed.clear();
				});
			});
```

## 3. Give up: one desktop

No extra actor. When the shell is not coming back, application windows are unminimized on the workspace already showing.

**🔷** `⏳` The wait callback gives up when the client that exited never reached ready (including one killed by the 30s timeout), or when `spawn_client` leaves `client_proc` null. Both fall through to the window loop at the end of the callback.

**🔷** `⏳` That loop walks `display.list_all_windows()`. It skips override-redirect windows (`DROPDOWN_MENU`, `POPUP_MENU`, `TOOLTIP`, `NOTIFICATION`, `COMBO`, `DND`, `OVERRIDE_OTHER`), `DESKTOP`, and `DOCK`. Everything else (`NORMAL`, `DIALOG`, `MODAL_DIALOG`, `TOOLBAR`, `MENU`, `UTILITY`, `SPLASHSCREEN`) is an application window. Move it onto the active workspace with `change_workspace` when it has a different workspace, then `unminimize` when `minimized` is set. The active workspace is `get_workspace_manager().get_active_workspace()`, or workspace 0 when that is null.

**ℹ️** A window with `is_on_all_workspaces()` is already on the visible workspace. The loop still unminimizes it and does not call `change_workspace` on it.

**ℹ️** The panel, overview, and wallpaper the shell added are gone. The plugin’s grey placeholder was dropped when the shell first painted a background, and teardown does not put it back. Behind the windows is whatever the stage still has, often empty.

**ℹ️** Frame rects stay. A window that was on another workspace keeps its position, now on this one. Clicking inside a window still goes to that app, so File → Save works when the control is on screen. Dragging that app’s own title bar still moves it: the app asks mutter, and mutter starts the grab. That grab is not the shell. Alt-drag, edge snap, and a frame drawn by the shell are gone with the keybindings and the shell actors.

**ℹ️** Desktop, dock, and override-redirect windows (dropdown menus, popups, tooltips, notifications, combos, drag-and-drop) stay where mutter put them.

**ℹ️** Then the user restarts the server and the desktop themselves. This view does not offer a control for that.

**🚫** Destroying `Meta.Window` or `Meta.WindowActor`. **🚫** A window list, an activate button per window, or any other chrome stand-in.

No fence here: the code is the tail of the wait callback in section 1.
