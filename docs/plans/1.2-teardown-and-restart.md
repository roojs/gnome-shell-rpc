# 1.2 — Teardown, restart, and a fallback while the shell is down

**User goal:** when the client goes away, remove the actors registered for that session. Then restart the client, with extensions off. If that restart fails, the windows stay so the user can save and close them, then restart the server and the desktop.

Checklist: `docs/guide-to-writing-plans.md`.

**Status:** **NEXT** — not active. Nested prove. No greeter install.

- **🔷** `⏳` Client gone: disconnect the signals and the other registrations for that session, then remove the actors.
- **🔷** `⏳` As soon as that teardown finishes, restart the client. Extensions off.
- **🔷** `⏳` If that restart fails, leave the windows. The user goes to each one, saves, and closes it, then restarts the server and the desktop.
- **💩** “Session” in the fences is that client’s RPC connection: actors, keybindings, grabs, barriers, and signal handlers leased on it. Application windows stay so the work can be saved.
- **ℹ️** `spawn_client()` does not watch the child (`src/server/rpc/Server.vala`). `Gsr.Server.Rpc.Connection.stopped` already fires once from `stop()`.
- **🚫** Destroying `Meta.Window` or `Meta.WindowActor`. **🚫** A window list, an activate button per window, or any other chrome stand-in. **🚫** A second spawn when the recovery client never reaches `notify_ready`. **🚫** Another GJS process. **🚫** Vendor `js/`.

**💩** A client that does reach `notify_ready` may die later and gets one new restart. A restart that never reaches ready does not spawn again.

**💩** Ready timeout is the literal `30` seconds in `teardown_client`. Timeout does not kill a hung client. It only refuses another spawn.

Named for the coding-standards gate (do not add others):

- fields on `Gsr.Server.Rpc.Server`: `client_proc`, `recovery_pending`, `restart_timeout_id`, `keybinding_names`, `event_handlers`
- methods `Gsr.Server.Rpc.Server.teardown_client`, `Gsr.Server.Rpc.Server.recovery_ready`

## 2. `teardown_client`

**💩** `⏳` Process exit and `stopped` both call this. The second trigger returns. Disconnect first. `actor.destroy()` emits, and the handlers still point at this connection.

**ℹ️** `connection.stop()` already disconnects `signal_subs` and then clears `leases` ([`signals-server.md`](../signals-server.md)). Calling it first drops the actor list, so teardown cannot destroy them. Disconnect, then destroy, then `stop()`.

**ℹ️** These are not in `signal_subs`, and the handler id is thrown away, so teardown cannot disconnect them yet:

- `Keybinding.add_keybinding` / `keybindings_set_custom_handler` — closure over the connection callback. Mutter still has the binding.
- `ClutterActor.add_hook` — `key_press_event.connect` / `key_release_event.connect` return value is ignored.
- `Actor.vfuncs` — `Live.Hook` on the actor. `destroy` during layout calls it.

**💩** `⏳` Keep those ids when they are added. Fields stay on `Server`. Not new fields on the libocrpc connection.

#### Add — `Server.teardown_client`

```vala
		private void teardown_client()
		{
			foreach (var connection in this.listen.connections) {
				foreach (var lease_id in connection.signal_subs.keys) {
					var subs = connection.signal_subs.get(lease_id);
					foreach (var name in subs.keys) {
						var sub = subs.get(name);
						var obj = connection.leases.get(lease_id);
						if (obj != null && sub.hid != 0) {
							GLib.SignalHandler.disconnect(obj, sub.hid);
						}
						subs.unset(name);
					}
				}
				foreach (var lease in connection.leases.values) {
					var hooked = lease as Gsr.Server.Clutter.Actor;
					if (hooked != null) {
						hooked.vfuncs.clear();
					}
				}
				var names = this.keybinding_names.get(connection);
				if (names != null) {
					foreach (var name in names) {
						this.display.remove_keybinding(name);
					}
					this.keybinding_names.unset(connection);
				}
				foreach (var lease in connection.leases.values) {
					var actor = lease as global::Clutter.Actor;
					if (actor == null || actor is global::Meta.WindowActor) {
						continue;
					}
					var hids = this.event_handlers.get(actor);
					if (hids != null) {
						foreach (var hid in hids) {
							actor.disconnect(hid);
						}
						this.event_handlers.unset(actor);
					}
					actor.destroy();
				}
				connection.stop();
			}
			if (this.recovery_pending) {
				return;
			}
			this.recovery_pending = true;
			this.spawn_client();
			this.restart_timeout_id = GLib.Timeout.add_seconds(30, () => {
				this.restart_timeout_id = 0;
				return GLib.Source.REMOVE;
			});
		}
```

#### Add — `Server.recovery_ready`

```vala
		public void recovery_ready()
		{
			if (this.restart_timeout_id != 0) {
				GLib.Source.remove(this.restart_timeout_id);
				this.restart_timeout_id = 0;
			}
			this.recovery_pending = false;
		}
```

`rpc_server` is already the field `start()` assigns.

## 3. What you see

No extra actor. This is the compositor with the shell’s actors gone.

**ℹ️** The panel, overview, and wallpaper the shell added are gone. The plugin’s grey placeholder was dropped when the shell first painted a background, and teardown does not put it back. Behind the windows is whatever the stage still has, often empty.

**ℹ️** You see only the workspace that was current. Other workspaces are not drawn on top of it. A window on workspace 2 stays there. Nothing in this plan moves it onto workspace 1. Switching workspace was a shell keybinding, and teardown removes those, so there is no way to reach the other workspace.

**ℹ️** A window that was minimized stays hidden. Unminimize was the shell. There is no button that brings it back.

**ℹ️** Clicking inside a window still goes to that app, so File → Save works when the control is on screen. Dragging that app’s own title bar still moves it: the app asks mutter, and mutter starts the grab. That grab is not the shell. Alt-drag, edge snap, and a frame drawn by the shell are gone with the keybindings and the shell actors.

**ℹ️** Then the user restarts the server and the desktop themselves. This view does not offer a control for that.
