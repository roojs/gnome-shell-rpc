# 1.2 — Teardown, restart, and a fallback while the shell is down

**User goal:** when the client goes away, remove the actors registered for that session. Then restart the client, with extensions off. If that restart fails, unminimize every application window and move those windows onto the workspace already on screen, so the user can save and close them, then restart the server and the desktop.

Checklist: `docs/guide-to-writing-plans.md`.

**Status:** **ACTIVE** — user 2026-10-03. Nested prove. No greeter install.

- **🔷** `⏳` Client gone: disconnect the signals and the other registrations for that session, then remove the actors.
- **🔷** `⏳` As soon as that teardown finishes, restart the client. Extensions off.
- **🔷** `⏳` If that restart fails, unminimize every application window and move those windows onto the workspace already on screen. The user saves and closes them, then restarts the server and the desktop.
- **💩** “Session” in the fences is that client’s RPC connection: actors, keybindings, grabs, barriers, and signal handlers leased on it. Application windows stay so the work can be saved.
- **ℹ️** `spawn_client()` does not watch the child (`src/server/rpc/Server.vala`). `Gsr.Server.Rpc.Connection.stopped` already fires once from `stop()`.
- **🚫** Destroying `Meta.Window` or `Meta.WindowActor`. **🚫** A window list, an activate button per window, or any other chrome stand-in. **🚫** A second spawn when the recovery client never reaches `notify_ready`. **🚫** Another GJS process. **🚫** Vendor `js/`.

**💩** A client that does reach `notify_ready` may die later and gets one new restart. A restart that never reaches ready does not spawn again.

**💩** Ready timeout is the literal `30` seconds in `teardown_client`. Timeout does not kill a hung client and does not spawn again. If `recovery_ready` has not run, that timeout is give-up and gathers the windows.

Named for the coding-standards gate (do not add others):

- fields on `Gsr.Server.Rpc.Server`: `client_proc`, `recovery_pending`, `restart_timeout_id`, `keybinding_names`, `event_handlers`
- methods `Gsr.Server.Rpc.Server.teardown_client`, `Gsr.Server.Rpc.Server.recovery_ready`, `Gsr.Server.Rpc.Server.gather_windows`

## 2. `teardown_client`

**💩** `⏳` Process exit and `stopped` both call this. The second trigger returns. Disconnect first. `actor.destroy()` emits, and the handlers still point at this connection.

**ℹ️** `connection.stop()` already disconnects `signal_subs` and then clears `leases` ([`signals-server.md`](../signals-server.md)). Calling it first drops the actor list, so teardown cannot destroy them. Disconnect, then destroy, then `stop()`.

**ℹ️** These are not in `signal_subs`, and the handler id is thrown away, so teardown cannot disconnect them yet:

- `Keybinding.add_keybinding` / `keybindings_set_custom_handler` — closure over the connection callback. Mutter still has the binding.
- `ClutterActor.add_hook` — `key_press_event.connect` / `key_release_event.connect` return value is ignored.
- `Actor.vfuncs` — `Live.Hook` on the actor. `destroy` during layout calls it.

**💩** `⏳` Keep those ids when they are added. Fields stay on `Server`. Not new fields on the libocrpc connection.

#### Add — `Server.teardown_client`

```vala
		private void teardown_client()
		{
			foreach (var connection in this.listen.connections) {
				foreach (var lease_id in connection.signal_subs.keys) {
					var subs = connection.signal_subs.get(lease_id);
					foreach (var name in subs.keys) {
						var sub = subs.get(name);
						var obj = connection.leases.get(lease_id);
						if (obj != null && sub.hid != 0) {
							GLib.SignalHandler.disconnect(obj, sub.hid);
						}
						subs.unset(name);
					}
				}
				foreach (var lease in connection.leases.values) {
					var hooked = lease as Gsr.Server.Clutter.Actor;
					if (hooked != null) {
						hooked.vfuncs.clear();
					}
				}
				var names = this.keybinding_names.get(connection);
				if (names != null) {
					foreach (var name in names) {
						this.display.remove_keybinding(name);
					}
					this.keybinding_names.unset(connection);
				}
				foreach (var lease in connection.leases.values) {
					var actor = lease as global::Clutter.Actor;
					if (actor == null || actor is global::Meta.WindowActor) {
						continue;
					}
					var hids = this.event_handlers.get(actor);
					if (hids != null) {
						foreach (var hid in hids) {
							actor.disconnect(hid);
						}
						this.event_handlers.unset(actor);
					}
					actor.destroy();
				}
				connection.stop();
			}
			if (this.recovery_pending) {
				this.gather_windows();
				return;
			}
			this.recovery_pending = true;
			this.spawn_client();
			if (this.client_proc == null) {
				this.gather_windows();
				return;
			}
			this.restart_timeout_id = GLib.Timeout.add_seconds(30, () => {
				this.restart_timeout_id = 0;
				if (this.recovery_pending) {
					this.gather_windows();
				}
				return GLib.Source.REMOVE;
			});
		}
```

#### Add — `Server.recovery_ready`

```vala

		{
```

## 3. Give up: one desktop

No extra actor. When the shell is not coming back, application windows are unminimized on the workspace already showing.

**🔷** `⏳` Give up inside `teardown_client` when `recovery_pending` is already set (the recovery client has gone and `recovery_ready` did not run), when `spawn_client` leaves `client_proc` null, or when the 30s timeout fires while `recovery_pending` is still set. Each of those calls `gather_windows`.

**🔷** `⏳` `gather_windows` walks `display.list_all_windows()`. An application window is `NORMAL`, `DIALOG`, `MODAL_DIALOG`, `UTILITY`, `TOOLBAR`, `MENU`, or `SPLASHSCREEN`. Move it onto the active workspace with `change_workspace` when it has a different workspace, then `unminimize` when `minimized` is set. The active workspace is `get_workspace_manager().get_active_workspace()`, or workspace 0 when that is null.

**ℹ️** A window with `is_on_all_workspaces()` is already on the visible workspace. `gather_windows` still unminimizes it and does not call `change_workspace` on it.

**ℹ️** The panel, overview, and wallpaper the shell added are gone. The plugin’s grey placeholder was dropped when the shell first painted a background, and teardown does not put it back. Behind the windows is whatever the stage still has, often empty.

**ℹ️** Frame rects stay. A window that was on another workspace keeps its position, now on this one. Clicking inside a window still goes to that app, so File → Save works when the control is on screen. Dragging that app’s own title bar still moves it: the app asks mutter, and mutter starts the grab. That grab is not the shell. Alt-drag, edge snap, and a frame drawn by the shell are gone with the keybindings and the shell actors.

**ℹ️** Desktop, dock, and override-redirect windows (dropdown menus, popups, tooltips, notifications, combos, drag-and-drop) stay where mutter put them.

**ℹ️** Then the user restarts the server and the desktop themselves. This view does not offer a control for that.

**🚫** Destroying `Meta.Window` or `Meta.WindowActor`. **🚫** A window list, an activate button per window, or any other chrome stand-in.

#### Add — `Server.gather_windows`

```vala
		private void gather_windows()
		{
			var mgr = this.display.get_workspace_manager();
			var workspace = mgr.get_active_workspace();
			if (workspace == null) {
				workspace = mgr.get_workspace_by_index(0);
			}
			if (workspace == null) {
				return;
			}
			foreach (unowned global::Meta.Window window in this.display.list_all_windows()) {
				switch (window.get_window_type()) {
				case global::Meta.WindowType.NORMAL:
				case global::Meta.WindowType.DIALOG:
				case global::Meta.WindowType.MODAL_DIALOG:
				case global::Meta.WindowType.UTILITY:
				case global::Meta.WindowType.TOOLBAR:
				case global::Meta.WindowType.MENU:
				case global::Meta.WindowType.SPLASHSCREEN:
					break;
				default:
					continue;
				}
				if (!window.is_on_all_workspaces()) {
					var current = window.get_workspace();
					if (current != workspace) {
						window.change_workspace(workspace);
					}
				}
				if (window.minimized) {
					window.unminimize();
				}
			}
		}
```
