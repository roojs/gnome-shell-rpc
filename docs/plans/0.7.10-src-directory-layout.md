## What actually goes over RPC

**🔷** This repo is **not** “Mutter-only RPC” anymore (that was plans **0.1–0.2**). The nested product is:

- **One OLLMrpc socket** between compositor and shell process.
- **Client typelibs** that look like stock **Meta-16**, **Clutter-16**, **St-16**, **Shell-16** to GJS — each method forwards to the compositor.
- **Server side** runs the **real** mutter + **real distro libst**; **`server/rpc/helper/*`** implements the server end of those wire calls (Meta windows, Clutter actors, St widgets, Shell globals, …).

So when we say **`server/rpc/`**, read it as **compositor-side transport + dispatch for the whole stubbed GI graph**, not “RPC inside libmutter only”. The early **`GnomeShellRpc.Ui.Window`** DTOs are a **small parallel** wire schema (fake-shell / **`list_windows`** era); **`init.js`** path is almost entirely **`Meta-*` / `Clutter-*` / `St-*` / `Shell-*`** method names on OLLMrpc.

**ℹ️ Legacy names** (keep for now; fix in a later rename pass if we want):

| Name | Says | Closer truth |
| ---- | ---- | ------------ |
| **`mutter-rpc`** (binary) | Mutter compositor host | Compositor process + plugin + **all** server relays |
| **`libmutter-rpc-16`** | Mutter client lib | **Meta-16-shaped** client `.so` only (Clutter/St are separate **lib\*** ) |
| **`gnome-shell-rpc`** | Shell | Accurate — GJS host |
| **`GnomeShellRpc.Rpc`** / **`server/rpc/`** | Generic “rpc” folder | OLLMrpc listener + **Helper** registry for every namespace we stub |

**⏳** 🔷 Phase 1: user choice on **binary/pkg renames** (e.g. compositor binary vs keeping **`mutter-rpc`** for muscle memory). **⏳** Layout-only option: rename **`server/rpc/` → `server/ollmrpc/`** (transport) and **`server/helper/`** at server top level (today **`rpc/helper/`**) so “rpc” is not the umbrella for St/Shell work — only if meson churn is worth it.

## Naming rule

**🔷** Directory name = **library name**, **gresource**, **generator tool**, or **test binary**.

| Name | Meaning |
| ---- | ------- |
| **`shared/`** | **All Vala compiled into both server and client** for OLLMrpc serializable types — today split across **`shared/`** + **`ui/`**, target **one tree**. Includes **`Rectangle`**, **`Window`**, **`Display`**, **`Workspace`**, **`Compositor`**. Not under **`server/`** or **`client/lib*`**. |
| **`server/`** (top level) | **`mutter-rpc`** executable — **`Main.vala`** ( **`Meta.Context`**, process entry ) and **`Plugin.vala`** ( **`Meta.Plugin`** registered via **`set_plugin_gtype`** ). Same pattern as **`client/ShellApplication.vala`** at **`client/`** root: no extra subfolder for the binary. |
| **`server/rpc/`** (maybe **`ollmrpc/`** + **`helper/`** later) | OLLMrpc **`Server`**, socket, bootstrap, and **`helper/*`** relays for **Meta, Clutter, St, Shell** (and shared DTO registration). Linked into **`mutter-rpc`** only — not a client **lib\***. |
| **`generator/`** | **`gi-stub-gen`**. |
| **`client/libmutter-rpc-16/`** … | Client **`.so`** / typelib sources. |
| **`client/gresource/`** | Vendor gnome-shell JS gresource. |
| **`client/*.vala`** | **`gnome-shell-rpc`** executable. |

**ℹ️** Why **`ui/`** exists as a sibling folder today: plan **0.3** moved only **`Rectangle`** into **`shared/`** first. For layout, merge **`ui/`** into **`shared/`**.

**ℹ️** Still **not** the same as **`Meta.Window`** or **`Rpc.Helper.Window`** — those are live server/client GI and helper code, not the shared serializable DTOs.

### What **`server/`** is (vs **`client/lib*`**)

**ℹ️** **`mutter-rpc`** is one **executable** that **links distro `libmutter-16`** (and **libst-16** on the server). We do **not** ship a separate “mutter plugin `.so`” in this repo — **`Plugin.vala`** is compiled **into** **`mutter-rpc`** and registered with **`Meta.Context.set_plugin_gtype`**. So **`server/`** top level = that binary’s entry + plugin class; **`server/rpc/`** = OLLMrpc + **all** server **Helper** relays in-process. Client side: separate **`client/lib*`** per typelib (**Meta**, **Clutter**, **St**, **Shell**) for GJS.

## Per-library map: generator, client overrides, server helpers

**🔷** **Overrides (`*.override.vala`) exist only on the client** — they patch **generated** stub methods to call `call_value("Meta-…")`, `call_value("Helper-…")`, etc. The compositor does **not** have override files; it uses **stock** Meta / Clutter / St from distro mutter + **`server/rpc/helper/*.vala`** for **`Helper-*`** wire classes and a few special **`Shell-*`** bins.

```text
                    generator/                    client (today gi-stub + shell-gi)
                    Meta.deny                     Meta_window_generated.vala (build/)
                    Meta.overrides        ──►     overrides/Window.override.vala
                    Clutter.overrides             overrides-clutter/Actor.override.vala
                    St.overrides                  overrides-st/Theme.override.vala
                    header-overrides/*.h          c-meta-shell-gaps.c, Runtime.vala
                                                          │
                                                          │ OLLMrpc socket
                                                          ▼
                    server/rpc/Server.vala            OLLMrpc.Gi.register("Meta"|"Clutter"|"St", "16")
                    real Meta.Display, libst          rpc/helper/Window.vala  → Helper-Window.*
                                                      rpc/helper/Actor.vala   → Helper-Actor.*
                                                      rpc/helper/St.vala      → St-Widget.new, …
```

### Meta-16 (`libmutter-rpc-16`)

| Layer | Today (→ target) | Role |
| ----- | ---------------- | ---- |
| Generator | `src/gi-stub-gen/Meta.deny`, `Meta.overrides` → **`generator/`** | Skip or tweak symbols before emit (e.g. opaque `Settings`, hand `BackgroundContent`). |
| Generated | `build/.../Meta_window_generated.vala` | Bulk of `Meta.Window`, `Meta.Display`, … client stubs. |
| Client overrides | `src/gi-stub/overrides/*.override.vala` → **`client/libmutter-rpc-16/overrides/`** | Hand RPC for callbacks / grabs / anything generator can’t emit. |
| Client hand | e.g. `gi-stub/PaintedContent.vala`, `c-meta-shell-gaps.c`, `Runtime.vala` | Non-generated Meta-adjacent types + client boot. |
| Server | **No overrides** | **`OLLMrpc.Gi.register("Meta", "16")`** on **real** typelib (`Server.vala`). Live **`Meta.Display`** + **`Ui.Display`** wrapper for notifications. |
| Server helpers | `src/rpc/helper/Window.vala`, `Display.vala`, `Context.vala`, … → **`server/rpc/helper/`** | Wire prefix **`Helper-Window`**, **`Helper-Display`**, … — server runs **`Meta.Window`** in-process. |

### Boot order (where pieces wire up)

| Side | File | What |
| ---- | ---- | ---- |
| Server | `src/rpc/Server.vala` | Socket, **`Helper.rpc_register()`**, **`OLLMrpc.Gi.register`** Meta/Clutter/St, live aliases |
| Server | `src/rpc/helper/namespace.vala` | Lists every **`Helper.*.rpc_register()`** (Meta, Clutter, St helpers in one function) |
| Client GJS | `src/gi-stub/Runtime.vala` | Connect socket, **`meta_register_bins()`**, **`st_register_bins()`**, Clutter register |
| Client host | `src/shell-client/ShellApplication.vala` | **`Runtime.register()`**, then **`Shell.Global.bind_display`**, then **`init.js`** |
