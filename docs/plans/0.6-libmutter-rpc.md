## Purpose

0.5 proved the layer by **prepending a typelib** and pretending to be mutter for **GJS smokes**. Gaps are **0**. This plan is the **product shape** of that layer: a client library GNOME Shell can treat as mutter.

- **🔷** `⏳` Build a **client-side** library **`libmutter-rpc-16`** that exposes **pretty much the same API mutter exposes to GNOME Shell**.
- **🔷** `⏳` GJS loads it as mutter: **`Meta-16.typelib`** + `shared-library` = our `.so`. `import Meta from 'gi://Meta'` / `gi.require('Meta', '16')` keep working. No GJS patch.
- **🔷** `⏳` In theory the GNOME Shell **build** points at this library (pkg-config / meson) instead of `libmutter-16` for the **shell process**. The compositor stays real mutter + this repo’s plugin.
- **🚫** Do not invent Meta / Shell / St symbols. Same rule as 0.5.
- **🚫** Do not install over `/usr/lib/.../libmutter-16.so`. Private prefix / `PKG_CONFIG_PATH` / `GI_TYPELIB_PATH` only.

```
today (0.5 smokes)                         target (0.6)

mutter + gnome-shell-rpc plugin            mutter + gnome-shell-rpc plugin
  real libmutter                             real libmutter (DRM, Wayland, Meta*)
         ▲                                            ▲
         │ libocrpc                                   │ libocrpc
         ▼                                            ▼
gjs-embed + GI_TYPELIB_PATH                GNOME Shell process (GJS + js/ui)
  libmetamini.so  (hand + bits)              libmutter-rpc-16.so
  Meta-16.typelib (ours first)               Meta-16.typelib (ours)
                                             GJS thinks this *is* mutter
```

**ℹ️** Two processes stay the holy grail: kill the shell client → windows stay. The plugin still completes map/minimize locally ([0.1](0.1-decouple-gnome-shell-vala-rpc.md)).

## What “same API as mutter” means

GNOME Shell talks to mutter in **two** ways. 0.6 owns the first; the second is a later, harder contract.

| Consumer | How it sees mutter today | 0.6 |
| --- | --- | --- |
| **GJS** (`js/ui`, `gi://Meta`) | `Meta-16.typelib` → `dlopen` `libmutter-16.so.0` → `ffi_call` `meta_*` | **🔷** Same typelib **name/version**; `shared-library` = **`libmutter-rpc-16.so`**; same `c:identifier`s. This is “delivers mutter to GJS.” |
| **C** (`libst`, `libshell`, client `main`) | `#include <meta/…>` + link `-lmutter-16` | **🔷** Same **public headers** + same **`meta_*` symbols**; link **`-lmutter-rpc-16`**. See **C API** below. |

**ℹ️** Distro `libmutter-16.pc`: `typelibdir` / `girdir` under `…/mutter-16`, `Libs: -lmutter-16`, `Cflags: -I…/mutter-16`. GJS never reads those headers — only the typelib + `.so`.

**ℹ️** gnome-shell JS pins the version at compile time (`js/misc/config.js` `LIBMUTTER_API_VERSION` → `gi.require('Meta', '16')`). Keep namespace **`Meta`** version **`16`**. Rename the **`.so`**, not the typelib.

---

## Anti-pattern: prepend typelib on stock `gnome-shell`

**🚫** `GI_TYPELIB_PATH=./build/src gnome-shell` on a binary that still **links and starts** real libmutter.

That process would **be** the compositor **and** load a second `Meta-16` (ours) into GJS. Two Meta type graphs, one address space. The 0.5 smokes never did this — they used **`gjs-embed`**, not the session `gnome-shell`.

**Right:** rebuild / run a **client** that does **not** start a compositor. Real mutter is the other process.

---

## C API — same public headers, our `.so`

**🔷** GNOME Shell C is written against mutter’s **public** `meta/*.h`. That is the contract. `libmutter-rpc` should satisfy it: compile those sources with **those headers**, link **our** library. Do **not** treat header match as a separate impossible ABI.

**ℹ️** Public GObject types are **opaque** (`typedef struct _MetaWindow MetaWindow` in `meta/types.h`). Callers use `meta_window_*` and `META_WINDOW()` macros, not mutter’s private instance fields. Our Vala `Meta.Window` does **not** need the same instance layout as compositor `MetaWindow`.

**ℹ️** Vala already emits the header names: `namespace Meta` + `class Window` + `minimize()` → **`meta_window_minimize`**. That is the same `c:identifier` GJS `ffi_call`s. `nm` on distro `libmutter-16.so.0` is unversioned `T meta_window_has_focus` (ELF `Base`).

**🔷** `⏳` If a generated C name ever drifts from a header (ctor, property accessor, `get_type`): fix with Vala `[CCode (cname = "…", cheader_filename = "meta/window.h")]` **or** a thin C `.c` that wraps `meta_*` from the header onto the generated symbol. Headers stay mutter’s; we implement them.

**🔷** Boxed types that **are** laid out in public headers (`MetaStrut`, `MetaButtonLayout`, …) already have to match for RPC memcpy — same requirement for C stack allocation.

**Compile vs link:**

| | |
| --- | --- |
| **Cflags** | Stock mutter `-I…/mutter-16` (`meta/window.h`, …). GIR was generated from these files. **Reuse them** — do not invent a second header tree unless Vala forces it. |
| **Libs** | `-lmutter-rpc-16` (and real Clutter/Mtk as today) |

**🚫** Install over distro `libmutter-16.so`. pkg-config name stays **`libmutter-rpc-16`**, not a fake `libmutter-16.pc`.

| Knob | 0.6 |
| --- | --- |
| pkg-config **`libmutter-rpc-16`** (typelibdir, `Libs`, `Cflags` that include **stock** mutter public headers) | **🔷** |
| Pretend to **be** `libmutter-16.pc` (same `Name:`) | **🚫** fights the distro; two compositors |
| Client **semantics** of `Context.start` (RPC connect, not DRM) | **🔷** behaviour — not a header problem. Today those methods are JS-side **no-ops** ([0.5.2](0.5.2-close-gi-stub-gaps.md) Phase 8) because **JS** never calls them. C `main.c` does. |
| St widgets on a **local** Clutter stage | **ℹ️** runtime / approach B — not “Vala cannot export `meta_*`” |

**ℹ️** Stock `src/main.c` still **starts a compositor**. Linking it at our `.so` without changing that path is the wrong **product**, not a proof that C symbols cannot match. Client `main` / [0.7](0.7-gnome-shell-rpc-client.md) owns that.

## Phase 1 — Package the client as `libmutter-rpc-16`

**🔷** `✔️` One `.so` GJS can `dlopen` as mutter. Typelib `shared-library` points at it. pkg-config for `typelibdir` / `Libs`. Hand-linked `meta-mini` still (Phase 2 / 0.5.2 Phase 9 links generated).

**Remove** (`src/meson.build`): `shared_library('metamini', …)` and `custom_target('Meta-16.typelib', … --shared-library, metamini_lib …)`.

**Replace with:** `shared_library('mutter-rpc-16', …)` linking **generated** `Meta_window_generated.vala` + Runtime + overrides + the small hand bits still required (`PaintedContent`, lease `Window` glue — whatever Phase 9 already needs). `g-ir-compiler --shared-library=<that .so>`.

**Add:** `libmutter-rpc-16.pc.in` (build-dir / private prefix):

```text
libdir=${prefix}/lib/...
typelibdir=${libdir}/mutter-rpc-16   # Meta-16.typelib — not stock mutter-16
girdir=${libdir}/mutter-rpc-16       # Meta-16.gir — not /usr/share/gir-1.0
Name: mutter-rpc
Description: Mutter-shaped RPC client (GJS + C Meta-16)
Requires: gio-2.0, gobject-2.0, mutter-clutter-16
Libs: -L${libdir} -lmutter-rpc-16
Cflags: -I${mutter_includedir}   # stock public meta/*.h — same contract as libmutter-16
```

**🚫** Do not install `Meta-16.typelib` / `Meta-16.gir` into stock mutter’s `typelibdir` / `girdir` or `/usr/share/gir-1.0`. Private `${libdir}/mutter-rpc-16/` only; consumers put that first on `GI_TYPELIB_PATH` / `GI_GIR_PATH`.

**ℹ️** Clutter / Cogl / Mtk stay **stock** mutter typelibs on the path **after** ours ([0.5.3](0.5.3-partial-clutter.md): do not shadow all of Clutter). `GI_TYPELIB_PATH=$our_typelibdir:$MUTTER_TL`.

**Add:** meson / docs one-liner for nested GJS:

```bash
MUTTER_TL=$(pkg-config --variable=typelibdir libmutter-16)
RPC_TL=$(pkg-config --variable=typelibdir libmutter-rpc-16)
GI_TYPELIB_PATH=$RPC_TL:$MUTTER_TL \
  ./build/src/gjs-embed --debug src/gjs-embed/meta-smoke.js
```

Existing nested spawn in `Rpc.Server` already prepends `bindir` + `MUTTER_TYPELIB_DIR` — keep that, pointed at the renamed `.so`.

## Phase 3 — GJS drop-in proof (this repo, nested)

**🔷** `✔️` Prove “delivers mutter to GJS” without a gnome-shell rebuild:

1. Nested `gnome-shell-rpc` (real mutter + plugin) as today.
2. Client: **`gjs-embed`** + `GI_TYPELIB_PATH` → **`libmutter-rpc-16`** `Meta-16`.
3. Basic smoke **`mutter-rpc-load.js`**: `get_shared_library('Meta')` contains **`mutter-rpc`** (not distro `libmutter-16`). `meta-smoke.js` asserts the same before launch.

```bash
# offline typelib check
MUTTER_TL=$(pkg-config --variable=typelibdir libmutter-16)
GI_TYPELIB_PATH=./build/src:$MUTTER_TL LD_LIBRARY_PATH=./build/src \
  ./build/src/gjs-embed --debug src/gjs-embed/mutter-rpc-load.js

# nested (plugin spawns the same script)
GI_META_SMOKE=mutter-rpc-load.js \
  dbus-run-session ./build/src/gnome-shell-rpc --wayland --nested
```

**🚫** Eval full `js/ui/init.js` / `main.js` as a Phase 3 exit. That needs `gi://Shell`, `gi://St`, `global`, stage chrome ([0.5](0.5-gnome-shell-js-layer.md) approach A vs B).
