## Why (feasibility — short)

**ℹ️** Today every layout peer does roughly:

```
server preferred/allocate
  → Hook.emit (sync wait)
  → client Class *_vfunc slot
  → if GJS did not override: *_vfunc_fallback → chain
  → client Helper-Actor.base_preferred_* (ask still open)  OR  allocate chain=true
  → server base measure
```

Most mint actors are plain `St.BoxLayout` / `St.Label` / … with **no**
`vfunc_get_preferred_*` / `vfunc_allocate` in JS. Prove already shows
~hundreds of preferred asks and ~100 `base_preferred_*` in a few seconds
([`bugs/2026-09-13-ready-not-in-5s-prove.md`](../bugs/2026-09-13-ready-not-in-5s-prove.md)).
That is correctness; it is also **wasteful RPC**.

**ℹ️** The archived preferred hang taught us: “no local measure” must still
call `base_preferred_*` **while the ask is open** — not close-then-measure,
and not “throw to mean fallthrough” on the hot path
([`done/2026-09-12-after-ready-open-preferred-emit.md`](../bugs/done/2026-09-12-after-ready-open-preferred-emit.md)).
`LiveCallback` error replies stay for **real** failures only.

**Verdict:** selective measure registration is **feasible** and is the right
**0.8.1** performance track — not a correctness fix for 0.8 A.

## Preferred shape — detect Class-slot override on the client **🔷**

**🔷** Prefer **automatic detection at mint**, not a hand allowlist. GJS already
writes overrides into the GObject **Class struct** during
`GObject.registerClass` / class_init when the JS class defines
`vfunc_get_preferred_*` / `vfunc_allocate`. Those are the same stock-offset
slots our stubs expose as `*_vfunc` (what `mint_layout_relay` already calls).

**ℹ️** Detection is a pointer compare on the client at `mint_layout_relay`
(construct), before `Helper-Actor.create`:

```
baseline = Class of St.Widget (our chain / *_vfunc_fallback slot)
klass    = Class of this.get_type()

need_preferred_width  = klass->get_preferred_width  != baseline->…
need_preferred_height = klass->get_preferred_height != baseline->…
need_allocate         = klass->allocate             != baseline->…
```

Then only register / pass live hooks for the bits that differ. Null hook →
server never emits that measure. No first-call tax; no hand list to refresh.

**Why vs immediate-parent compare:** a GJS child that *inherits* a parent’s
`vfunc_allocate` without re-defining it keeps the **same** function pointer as
its parent. Comparing only to the immediate parent would miss those. Comparing
to the **St.Widget baseline** (the chain fallback we install) catches any
override anywhere below Widget — including inherited GJS trampolines.

**ℹ️** This is easy because the slots are set in the normal GType flow; we do
not need to parse JS or maintain 46 names. The audit list stays as a
**checklist / prove oracle**, not as the runtime source of truth.

**Caveat:** if a **Vala/C stub** subclass of Widget also replaces those Class
slots (not via GJS), detection would look like an override and we would still
emit once → client chain → `base_preferred` (today’s behaviour for that type).
Worth a quick stub audit when implementing; do not invent hand lists unless
that noise is large.

Rough picture:

```
construct / mint_layout_relay:
  bits = class_slots_differ_from_widget_baseline(this)
  if bits empty → no Helper-Actor hooks (server base only)
  else → callback_bind only for set bits → Helper-Actor.create(…)
```

## Fallback — hand allowlist **💩**

| # | Approach | Idea | Pros | Cons |
| - | -------- | ---- | ---- | ---- |
| P0 | **🔷** Class-slot vs Widget baseline at mint | Pointer compare on client | Automatic; matches GJS install; no first-call tax | Needs correct Class field / ABI; stub-side false positives |
| P1 | **💩** Hand allowlist + register | Explicit “these measure” | Simple; audit already listed ~46 | Easy to miss a type; churn |
| P2 | **💩** Server negative cache | After first chain, skip further emits | No client Class peek | Still pays first emit |
| P3 | **🚫** Error-as-capability | `reply_error` / throw = “no vfunc” | — | Rejected for preferred fallthrough |

**🔷** Default: **P0**. Keep the audit table as verification. Use **P1** only if
Class peek is wrong on our stubs.

## How we prove

1. Nested `./scripts/weston-gsr-prove.sh` (or session) with counts:
   - preferred / allocate **Hook.emit**
   - `Helper-Actor.base_preferred_*`
   - optional: mint log of capability bits vs type name
2. Before/after: same READY / A4 markers; **fewer** emits; Panel / UiActor
   still get JS measure; plain `St.BoxLayout` peers never emit.
3. Oracle: every Actor class in the audit that is constructed on the prove
   path should show non-empty bits; types not in the audit should be empty.
4. Missed detection → wrong chrome geometry — fix the Class peek, not a
   one-off name list (unless P0 is abandoned for P1).
