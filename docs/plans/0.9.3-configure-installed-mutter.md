# 0.9.3 — Configure for the installed mutter

**User goal:** Keep one git tree. Ship a separate package for each Ubuntu release we support, built on GitHub, and test each package on a virtual machine for that release. Each package is the RPC stack for that release’s GNOME Shell (`libmutter-rpc-16` on 25.04, `libmutter-rpc-18` on 26.04, and so on).

**Status:** **proposed**.

Checklist: [`docs/guide-to-writing-plans.md`](../guide-to-writing-plans.md).

Sub-plan of [`0.9-multi-shell-series.md`](0.9-multi-shell-series.md) Phase 1. The file split is the report in [`0.9.1-examine-26.04-requirements.md`](0.9.1-examine-26.04-requirements.md). This plan is what `meson setup` does with that split.

## Purpose

- 🔷 `⏳` `meson setup` looks at the installed mutter. `libmutter-18` configures the 18 build. `libmutter-16` configures the 16 build. Ninja then builds that configure.
- 🔷 `⏳` The vendored gnome-shell is the matching major. Mutter 16 keeps 48.x. Mutter 18 checks out 50.x when the tree is missing or is another major, then configure errors if the checkout is still the wrong major.
- 🔷 `⏳` An 18 configure compiles the 18 replacements from the 0.9.1 report, and the 16 files whose API did not change. A 16 configure stays on the sources it compiles today.
- 🔷 `⏳` Pkg-config modules, `gi-stub-gen` version arguments, sonames, typelib names, and `config.js` `LIBMUTTER_API_VERSION` / `PACKAGE_VERSION` follow that mutter.
- ℹ️ One configure, one mutter. A 25.04 machine has `libmutter-16` and stays a 16 build with no extra `-D` flag.
- 💩 Vendor pin for mutter 18 is the tag `50.0`, the same `.0` pin as `48.0`. The Ubuntu 26.04 package is gnome-shell 50.1. The check is the major (`50`), so `-Dgnome_shell_vendor_ref=50.1` is a matching override.

## Detection

**Why:** the build has to follow the mutter that pkg-config sees.

**Where:** `meson.build`, the `libmutter_dep` assignment, before `subdir('gnome-shell')`.

**Depends on:** none.

Probe `libmutter-18` first. When it is found, that configure is API 18 even if `libmutter-16` is also installed. Otherwise require `libmutter-16`.

#### Replace with

  'libmutter-18',
  version: ['>= 50', '< 51'],
  required: false,

## Vendored gnome-shell

**Why:** a mutter 18 configure that still embeds gnome-shell 48 JS is the wrong shell. The checkout check already re-pins a non-48 tree. The expected major follows the detected mutter.

**Where:** `gnome-shell/meson.build`, the block that sets `gnome_shell_target_ref` and the `vendor_major != '48'` checks. `gnome_shell_target_major` and `gnome_shell_target_ref` come from the parent `meson.build`.

**Depends on:** Detection.

The option default is `48.0`. On a mutter 18 configure that default means “use this mutter’s pin”, not “stay on shell 48”. `head`, `main`, and `''` do the same. Any other ref must start with `gnome_shell_target_major` plus a dot (`48.1`, `50.1`).

#### Remove

```meson
# Hard target while this project supports 48 only (ignore stale builddir "head").
gnome_shell_target_ref = '48.0'
ref_opt = get_option('gnome_shell_vendor_ref').to_lower()
if ref_opt == '' or ref_opt == 'head' or ref_opt == 'main'
  ref = gnome_shell_target_ref
elif ref_opt.startswith('48.')
  ref = get_option('gnome_shell_vendor_ref')
else
  error(
    'gnome_shell_vendor_ref=@0@ is not a 48.x ref — this project only targets gnome-shell 48.\n'.format(
      get_option('gnome_shell_vendor_ref'),
    ) +
    '  Omit the option (defaults to 48.0) or pass e.g. -Dgnome_shell_vendor_ref=48.1',
  )
endif
```

#### Replace with

```meson
# Pin follows the mutter detected in the parent meson.build.
# Option default 48.0 means "use that pin", including 50.0 when mutter is 18.
ref_opt = get_option('gnome_shell_vendor_ref')
ref_opt_lower = ref_opt.to_lower()
if ref_opt_lower == '' or ref_opt_lower == 'head' or ref_opt_lower == 'main' or ref_opt == '48.0'
  ref = gnome_shell_target_ref
elif ref_opt.startswith(gnome_shell_target_major + '.')
  ref = ref_opt
else
  error(
    'gnome_shell_vendor_ref=@0@ is not a @1@.x ref — this configure is mutter @2@, gnome-shell @1@.\n'.format(
      ref_opt,
      gnome_shell_target_major,
      mutter_api_version,
    ) +
    '  Omit the option or pass e.g. -Dgnome_shell_vendor_ref=@0@'.format(gnome_shell_target_ref),
  )
endif
```

## LLM notes

- Do not add a `-Dmutter_api` option. The installed pkg-config module is the switch.
- Do not configure both APIs in one build directory.
- Do not rename source directories so that a shared file lives in an unnumbered directory.
- Do not edit `.github/workflows/x-debian.yml` or `x-rpm.yml` in this plan. The 25.04 image has `libmutter-16`. The 26.04 package job is the later bullet on [`0.9-multi-shell-series.md`](0.9-multi-shell-series.md).
- Do not rewrite `gnome-shell/README.md` here.
- Shell 50 `js/misc/config.js.in` may add a substitution this tree does not set. Add that key when the gresource compile names the missing token.
- `Cogl-16.metadata`, `Clutter-16.metadata`, and `Meta-16.metadata` stay the vapigen metadata for both APIs until a symbol in them fails on 18.
