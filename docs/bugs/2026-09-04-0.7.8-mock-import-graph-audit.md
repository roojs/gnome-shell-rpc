## The bug

During real shell startup, memory inside the JS engine gets corrupted. The process aborts with `double free or corruption (out)`.

---

## What we know

- **Repro:** `./scripts/gi-rpc-smoke.sh run` (real `init.js`, fake compositor). About half of runs crash.
- **Trace:** `GI_RPC_REGISTER_CLASS_TRACE=1 ./scripts/gi-rpc-smoke.sh run` — on crash, read the last `register-class-trace` lines.
- **Current pin:** crash runs stop after registering notification UI classes **`NotificationMessage`** and **`MediaMessage`** — both live in **`messageList.js`**.
- **Earlier fix in same file:** `MessageView` needed `St.Scrollable` on our `St.Viewport` stub. That class of problem (wrong/missing St stub) is the leading hypothesis for this crash too.
- **Nested (old):** sometimes last logged class was **`ActionEditor`** in pad OSD — different symptom line, may be same underlying corruption showing up later on real Mutter.

## Next step

1. **Prove the pin:** rebuild with `-Dgi_rpc_js_overlay_message_list=exit` — overlay replaces `ui/messageList.js` in the embedded gresource and calls `Meta.Context.terminate()` before any `registerClass`. If full `init.js` then stops crashing, the bug is definitely in that file’s evaluation.
2. Bisect **inside `messageList.js`** — which class registration or stub (`St.Button`, `St.Viewport`, …) triggers the abort.
3. Compare that widget’s stub against real Mutter/GIR (same method as the `MessageView` fix).
4. When mock startup is clean, confirm once on nested.

### Replacing individual JS files

| Mechanism | Works for full `init.js`? | How |
| --- | --- | --- |
| **Gresource overlay** (`src/shell-js/`) | **Yes** | `gnome.compile_resources` uses `source_dir: [build_dir, vendor]` — same path in the build dir wins (already used for `misc/config.js`). Add e.g. `src/shell-js/ui/messageList.exit.js` + `-Dgi_rpc_js_overlay_message_list=exit`. |
| **`GNOME_SHELL_JS_DIR`** | No for typical imports | On GJS search path after `resource:///`, but modules loaded from the gresource still resolve `./foo.js` relative to the resource URL. |
| **`GI_RPC_GJS_EMBED_DIR`** | No (same reason) | Extra search path for smokes / embed scripts, not resource-relative imports. |
| **`GNOME_SHELL_JS_EXTRA_DIRS`** | No (gjs-embed only today) | Colon-separated extra dirs in `gjs-embed/Application.vala`; `gnome-shell-rpc` does not read it yet. |

To bisect: copy the vendor file into `src/shell-js/ui/`, trim or stub classes, rebuild gresource (ninja), rerun smoke.

```bash
meson setup build -Dgi_rpc_js_overlay_message_list=exit --reconfigure
ninja -C build
./scripts/gi-rpc-smoke.sh run 2>&1 | rg 'overlay|double free|Aborted'
```
