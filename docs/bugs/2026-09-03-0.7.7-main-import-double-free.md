# 0.7.7 — `main.js` import double-free (nested boot blocker)

**Status:** open — **intermittent heap corruption**, trigger narrowed, **alloc site unknown**  
**Plan:** [`docs/plans/0.7.7-thin-shell-bootstrap.md`](../plans/0.7.7-thin-shell-bootstrap.md)  
**Last updated:** 2026-09-03

---

## What we know (stop re-proving)

| Fact | Detail |
| --- | --- |
| **Where** | `gnome-shell-rpc` child, **~300ms after boot**, loading **`main.js` graph** — not shutdown |
| **What** | glibc heap error: `double free or corruption (out)` or `realloc(): invalid next size` |
| **Intermittent** | Same binary/config: sometimes dies, sometimes runs 28s with only Scrollable CRITICALs |
| **Typical fail sequence** | `MessageView` Scrollable CRITICALs → immediate heap abort (when it fails) |
| **Not required** | Full `init.js` / `main.start()` — `main-import-smoke` and `main-dissect-smoke` hit it |
| **Safe path** | `environment.js` only; GI/St import smokes; no `main.js` subgraph |
| **ASAN build** | `build-asan/` (`-Db_sanitize=address`) — **15+ runs, zero repro**; timing/redzones likely hide a race/use-after-free |
| **Viewport override** | **Not the sole cause** — override off still double-frees ~2/3; override with fields always fails in bisect |

## Main.js dissection (use this, not full init)

```bash
# Same crash class, faster:
GI_META_SMOKE=main-dissect-smoke GI_MAIN_SMOKE_MODULE=components.js \
  timeout 18 dbus-run-session -- ./build/src/mutter-rpc --wayland --nested

# ASAN (when it repros):
ASAN_OPTIONS=symbolize=1:abort_on_error=1:detect_leaks=0 \
  GI_META_SMOKE=main-dissect-smoke GI_MAIN_SMOKE_MODULE=components.js \
  timeout 18 dbus-run-session -- ./build-asan/src/mutter-rpc --wayland --nested
```

| Module | Typical result |
| --- | --- |
| `components.js` | heap abort **or** loads OK (intermittent) |
| `overview.js` | Scrollable CRITICAL → heap abort **or** OK |
| `panel.js` | `realloc(): invalid next size` (separate corruption?) |
| `layout.js`, `dnd.js`, `screenshot.js` | Scrollable CRITICAL, often survives |

## What we do **not** know

- **Which allocation is double-freed** — ASAN never fired; GDB child backtrace not captured
- **Single vs multiple bugs** — `components.js` once failed without MessageView CRITICAL in log
- **Correct `St.Scrollable` fix** — override work was inconclusive; do not ship null/non-nullable hacks

## Working hypothesis (one line)

GJS registers `Gjs_ui_messageList_MessageView` (and other `St.Viewport` subclasses) while stub `St.Viewport` does not properly expose `St.Scrollable`; GObject class setup corrupts heap — **race or layout dependent**, hence intermittent and ASAN-clean.

## Next step (one, not ten)

**GDB on the child at fail time** with breakpoint on `g_type_register_static` / catch on `MessageView` registration, or run **non-ASAN** client under GDB with `catch syscall exit_group` after Scrollable CRITICAL — get **one** backtrace, then fix. No more override/Vala guessing until that.
