# Desktop Icons shows as gjs, and the cube swipe does not rotate

**Status:** Open. The virtual machine is the session. `src/` stays unchanged.

`alan@192.168.122.115` (`ubuntu2604`), tty2, `/usr/bin/gsr-server --wayland` (no `--debug`). Restarts of `org.gnome.ShellRpc@wayland.service` on 2026-11-12 reproduce the double launch. The 10:29 login had the same pair and, separately, `parent is null` from `desktop-cube` `extension.js:876` during the panel overview toggle. That cube line has not been reproduced on today's restarts.

Every restart launches DING twice. The second launch is the extension's 3s timer. The first `ding.js` is a live Wayland client on the private socket (`WAYLAND_SOCKET=3`, the socketpair inode is also open in `gsr-server`). It creates an `xdg_toplevel` titled `Desktop Icons 1` with app id `gjs`, receives `configure(1280, 768)`, attaches a buffer, and gets `wl_callback.done`. Mutter emits `window-created` for that window. Two seconds later `list_all_windows` still contains it (`1280x800`, maximized) and `get_compositor_private()` is null, so `get_window_actors()` is empty and `Shell.WM::map` never runs. `owns_window` is never called. Holding the process for 60s does not create the actor. The timer then `force_exit`s it. The `Meta.Window` stays in `list_all_windows` with no actor.

The second `ding.js` maps in the same second it starts (`DING map`, `owns=true`, `actors=1`) and is claimed. `list_all_windows` then has two `Desktop Icons 1` windows: the new one with an actor, and the first one still without. The unmapped window is never hidden from the window list, because hide runs only after a claimed map. That is the extra `gjs` entry.

Clamping the Gtk size request to height 768 still left the first window without an actor (frame `1280x798`). An idle before the first launch did not change it. `g_subprocess_get_if_exited: assertion 'pid == 0' failed` still prints four times per launch, on a child that has not exited. It does not schedule the second launch.

The guest copies of `ding@rastersoft.com` still have temporary `DING` logs. A tty3 `GI_META_SMOKE=ding-new-subprocess` run does not reproduce this: the client either never lists a window (`miss no-owned-window`) or, for a plain Gtk window, stays inside `show_all`. On the user session, `actor-probe@gsr` launched a maximized 1280×800 `Probe Window`. Two seconds later that window was in `list_all_windows` with `get_compositor_private()` null (`miss no-actor`), while a `Desktop Icons 1` window in the same list had an actor. The probe is not in `enabled-extensions` now. No `src/` edit.

`~/.cache/gnome-shell-rpc/weston-autolaunch-prove.log` on this host ends `ding-icons/ui/init: ok` at 08:44:07. That extension uses `spawnv` on mutter 16. It is not this failure.
